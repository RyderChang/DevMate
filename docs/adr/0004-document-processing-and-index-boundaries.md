## 背景

DEV-016 建立原文件接入与恢复边界。[实现 PR #30](https://github.com/RyderChang/DevMate/pull/30)
在编写时尚未合并，解析、分块、Embedding 和 Qdrant 尚未实现。
需要区分原文件存储、派生文本与向量投影，避免将 `STORED` 误解为知识可检索，
或将解析任务扩大为整个 RAG 系统。

## 决策

### 分开实施

DEV-017 只实现 UTF-8 `.txt` / `.md` 的确定性文本解析、版本化分块、
MySQL 派生片段、手动触发 API 及有界恢复。
不新增通用解析依赖，不触发付费模型，不接入 Qdrant 或 RAG 对话。
Embedding 与向量索引另立任务，检索与对话引用再单独验收。

原字节及原 SHA 不变。文本视图仅去除首个 BOM、统一 CRLF/CR 为 LF，保留 Markdown 字面文本。
片段位置指向规范化文本的 Unicode code point 半开区间，不冒充原字节位置。
使用版本化确定性规则：目标 1,000、寻找边界下限 800、硬上限 1,200、重叠 100 个 code point。
完整算法、额度、API、状态与验收以任务书第 3 至 9 节为准。

### 数据与权限

MySQL 是归属、处理代、片段正文、幂等、额度和发布状态的真相源；MinIO 仍只保存原文件。
Qdrant 后续仅承载可重建向量投影，不复制片段正文，不作为授权或生命周期真相源。
派生片段持久化是后续任务的新职责，不改写 ADR 0003 对 DEV-016 的原文件存储约束。
schema 仅用新 Flyway migration 扩展，主键沿用自增 BIGINT。

所有处理与内部正文读取同时验证用户、项目、文档和活动代。
后续向量检索强制用户/项目过滤，再核对 MySQL 中的活动代与删除状态。
正文保持不可信数据属性；不渲染、执行、抓取外链或写入日志。

### 版本、发布与删除

存储、处理、索引维护独立状态，分别用 `STORED`、`CHUNKED`、`INDEXED` 表示各自完成。
暂存代完整校验后原子发布，部分片段或向量永远不对读取方可见。
来源原 SHA、解析版本、分块策略和后续 Embedding 规格均随代保存，不能原地混用或覆盖。
新代失败保留仍有效旧活动代；重复任务可恢复，旧失败记录保持终态。

删除在与发布互斥的事务中撤销可见性并取消处理，优先于迟到回调。
清理依据持久保存至原文件及派生内容确认清理完成，禁止先删父元数据导致残留无法追踪。
后续远端 upsert 的不确定结果同样不能仅凭租约过期或一次不存在判定结束。
这些要求扩展派生内容清理，不放宽 ADR 0003 的存储终态和未知结果约束。

### 外部模型

Embedding 必须通过 AI Gateway 的独立能力，不能复用聊天输出或从 knowledge 引用提供商 SDK。
本次不选择提供商、模型、维度、距离规则、tokenizer、费用预算、SDK 或 Qdrant 版本。
字符分块不承诺满足 token 上限；这些选项须在索引任务开始前另行确认并验证。

## 备选方案

- 解析、Embedding、Qdrant 和 RAG 一次实现：验收和失败恢复范围过大，无法独立证明各阶段完成。
- 先按模型 token 分块：可以紧贴模型窗口，但在模型/tokenizer 尚未选择时会提前绑定依赖；首版选择可复现字符规则。
- Markdown AST 与代码块感知：语义保留更好，但需要额外依赖、格式规则与安全测试；后续以新版本引入。
- 只在内存保存片段，或直接把全文写入向量存储：缺少稳定来源、独立恢复和权限真相源，不采纳。
- 上传后自动处理：体验直接，但上传会隐含消耗派生资源；首版采用显式触发。

## 后果

每阶段有独立产物、验证与失败状态，派生内容可重建，模型故障不会改变原文件存储状态。
代价是维护暂存代、额度、原子发布、删除交接和恢复记录。
字符规则可能切开语义或代码块，规范化位置与原字节位置不同；首版明确保留这些限制。
新策略与向量模型变化会增加重建工作，须计入资源与费用预算。
