# ADR-0001：首版采用模块化单体

- 状态：Accepted
- 日期：2026-09-09

## 背景

DevMate 是个人作品集项目，但覆盖项目空间、对话、知识库、GitHub 分析、代码审查和测试生成等多项能力。系统需要清晰的业务边界，同时应控制早期部署、调试和运维复杂度。

## 决策

采用前后端分离的 monorepo。后端首版实现为模块化单体，异步任务最初与主应用共享代码库和业务数据库。模块只能通过公开的应用服务边界协作，禁止跨模块直接调用 Mapper。

## 备选方案

- 从首版开始拆分微服务：隔离更强，但会过早增加部署、事务、可观测性和本地开发成本；
- 不划分模块的单体：起步简单，但难以保持领域边界，也会增加后续拆分成本。

## 后果

单一后端部署单元便于本地开发、部署和端到端测试。相应代价是团队必须主动维护模块依赖方向和应用服务边界，避免演化为无边界单体。

## 后续行动

持续度量异步任务吞吐、资源竞争和模块发布节奏。只有出现真实的吞吐、资源隔离或独立发布需求时，才优先评估拆分 AI Worker 或 Index Worker。
