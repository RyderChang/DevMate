# 0002：AI Gateway 与应用侧会话状态

- 状态：Accepted
- 日期：2026-09-20

## 背景

项目对话、后续 RAG、代码审查和测试生成都需要调用外部模型，但业务模块不能绑定单一提供商，
也不能依赖提供商托管的会话状态。模型调用还必须具备可测试、可审计、默认关闭和不泄露敏感内容的边界。

## 决策

DevMate 定义提供商无关的 AI Gateway 请求、响应和稳定异常类型。首个基础设施适配器使用同步、
非流式 OpenAI Responses API；适配器之外不出现 OpenAI HTTP DTO、URL 或认证字段。

DevMate 在 MySQL 保存对话、可见消息和调用元数据。每次请求由应用选择有界历史并重新构造
`project-chat-v1` 提示词，不使用提供商 conversation 或 `previous_response_id`。请求显式设置
`store=false`、`stream=false`，且不声明工具、文件、图像、音频或后台能力。

同一对话通过数据库租约限制为一个在途生成，并通过 `(conversation_id, client_request_id)`
唯一约束提供幂等。远程调用位于数据库事务之外；调用前后分别使用短事务持久化状态。

## 影响

- 业务模块可用 Stub 替换 Gateway，自动化测试无需密钥和公共网络。
- 模型、模板版本、Token、耗时和状态可审计，但不保存原始请求、原始响应或隐藏推理。
- 应用负责上下文裁剪和会话一致性，增加了数据库编排复杂度。
- DEV-013 不支持流式输出、工具调用、多提供商路由或提供商托管会话；这些能力需单独决策。
