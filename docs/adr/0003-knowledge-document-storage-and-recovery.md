# 0003：知识文档存储与恢复边界

- 状态：Accepted
- 日期：2026-09-27
- 关联任务：[DEV-016](../tasks/DEV-016-knowledge-document-storage.md)
- 确认依据：所有者在本次审核会话中明确要求“修订上述文档、记录第二阶段确认，再确认 016 待定方案与存储 ADR”。本 ADR 根据该授权采纳原任务书方案并明确失败恢复语义。
- 实施状态：功能尚未实施；架构接受与环境验证分开记录，后续依赖/环境核验见[实施前核验记录](../development/storage-preflight.md)。

## 背景

第二阶段 AI 对话已确认收口。第三阶段先建立原文件接入能力，后续才实施解析、分块与向量检索。
MySQL 事务无法与对象存储写入原子提交，因此必须在响应丢失、进程崩溃、并发删除时保存恢复依据，
同时保证用户与项目隔离、资源限额和可解释的重试行为。

## 决策

### 存储职责与范围

MySQL 是文档归属、状态、幂等、容量预留和补偿记录的真相源；原始字节存入私有对象存储。
首个适配器对接 MinIO 的 S3 兼容接口，SDK 类型仅存在于 knowledge 的 infrastructure 内。
应用服务依赖最小存储接口：写入、受限读取、完整性核对与幂等删除。没有公网下载、签名 URL 或浏览器直传。
本次不接入 Redis、Qdrant、解析器、Embedding、前端或通用任务平台。

接入只接受 UTF-8 `.txt`/`.md`（允许 BOM），拒绝非法编码、NUL、空文件及纯空白内容。
单文件上限 5 MiB、multipart 请求上限 6 MiB，每项目最多 100 份未清理文档和 100 MiB 原文件字节。
文件名仅用于展示，最多 200 个 Unicode code point；禁止路径分隔符、控制字符及 `.`/`..`。
同名同内容可独立上传，不覆盖原文件。SHA-256 按原始字节计算，不能以 ETag 替代。
所有具体 API、输入校验与验收矩阵以关联任务书为准。

项目归属通过 project 公开应用服务校验，禁止跨模块 Mapper。project 需提供可持久恢复的删除交接
或内部查询边界，使扫描器发现软删除项目的残留文件；不能只依赖内存事件。
数据库主键沿用自增 BIGINT，新结构仅通过新增 Flyway migration 建立。

### 事务、幂等与终态

校验文件后，在短事务中原子完成项目有效性校验、幂等检查、额度预留和 `UPLOADING` 记录。
对象 key 在远程写入前持久化，由服务端生成；原文件上传在事务之外，完成后通过短事务及条件更新提交 `STORED`。
`STORED` 只表示原文件存储完成，不表示知识可检索。请求唯一约束为
`(owner_user_id, project_id, client_request_id)`，指纹包含规范化文件名、类型、实际字节数和 SHA-256。

写入超时、数据库提交结果未知及崩溃均属于不确定结果，不直接认定失败。保留 `UPLOADING`，
由核对确认完整对象及项目有效后转 `STORED`；同 UUID、同指纹在确认前返回 409，成功后返回原文档 200。
恢复不重新上传原文件；对象确定缺失且无在途写入、完整性不符或其他确定不可完成情形才提交 `FAILED`。
数据库不可写时依赖先前持久化记录恢复，不保证异常处理的更新一定成功。

`FAILED` 是接入终态，不能回到 `UPLOADING` 或 `STORED`；后续只做清理，重放稳定返回 409。
调用方不得仅凭首次 503/504 自动生成新 UUID。预留前的校验、容量或配置拒绝不建立失败请求映射。
不同指纹复用 UUID 始终冲突，任何重放都先验证当前归属和项目有效性。

### 删除、容量和恢复

删除在短事务中标记 `DELETE_PENDING`，立即对普通读取隐藏；远程删除在事务外执行。
重复 DELETE 在待删除期间返回 202，清理后返回 404。项目软删除后所有文档 API 立即不可访问。
失败和待删除文档仍占额度，只有确认对象不存在且没有仍可写入的上传操作，才释放额度、删除文档元数据。
成功未删除文档持续保留幂等映射；失败或删除清理完成后，最小请求映射与终态再保留 24 小时，
过期后物理清理，窗口外同 UUID 按新接入处理。没有回收站。

数据库条件更新与操作租约防止旧响应覆盖删除状态，但租约过期不能阻止远端迟到 PUT。
无法确认写入已结束时必须保留定位和容量，继续核对或进入人工处理，不能凭一次对象不存在就清账。
鉴权失败、网络错误和核对超时均不能解释为对象不存在。

knowledge 内部扫描器每 60 秒扫描，每批最多 50 条；失败后的自动重试最多 5 次，
依次等待 1/2/4/8/16 分钟。扫描调度可能延后实际执行，不承诺精确删除 SLA。
上传总操作超时默认 30 秒、操作租约 2 分钟、实例并发上传上限 4；恢复只能在租约到期后领取。
扫描领取必须支持多实例条件更新；次数耗尽后保留原状态、定位、额度及安全错误码，转受控人工处理。
人工重试只恢复核对/清理，不得将 `FAILED` 或 `DELETE_PENDING` 改回成功。
所有时间与竞态均需可控时钟/屏障测试。

### 配置与安全

知识上传默认关闭，上传返回安全 503，既有认证、项目与对话不依赖存储凭据。
关闭时可读授权元数据、标记删除，但暂停对象清理；重新启用后恢复持久化待处理记录。
bucket 由环境准备流程创建为私有；应用不更改公共访问策略。生产 endpoint 要求 HTTPS，
仅隔离本地测试可显式使用 HTTP。凭据仅服务端环境注入，CI 临时凭据运行时生成。
日志与错误不含正文、文件名、对象路径、凭据或 SDK 原始响应；临时文件必须限制目录、容量和生命周期。

## 备选方案

- MySQL 保存原文件 BLOB：虽可将元数据与内容放在同一事务，但扩大数据库存储、备份和 I/O 负担，不符合已规划的文件存储职责。
- 宿主本地文件系统：隔离测试简单，但引入节点绑定与共享卷要求，不作为首个正式存储适配器。
- 浏览器直传及预签名 URL：减少应用带宽，但增加授权、上传确认及废弃对象回收流程，超出当前单文件有界接入范围。
- Redis 锁、内存队列或仅异常 catch 删除：无法独立提供持久恢复与事务容量约束，不能作为正确性基础。
- 通用任务平台或消息队列：当前只有存储补偿需求，先用模块内有界扫描，避免提前引入跨模块任务架构。

## 后果

原文件、业务状态与未来向量索引职责清晰，业务层可使用 Stub 测试，外部调用不占用数据库事务。
代价是必须维护跨存储状态机、幂等终态、容量预留、恢复扫描及人工处理路径。
未知结果可能持续占用容量；存储不可用、功能关闭或重试耗尽时，物理删除可能延迟。
回滚可关闭功能并回退兼容应用，但不能恢复已物理删除的原文件；备份保留政策需单独记录。
