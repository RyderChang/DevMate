# 0008：RAG 对话编排与引用快照的有界合同

- 状态：Accepted
- 日期：2026-09-29
- 关联：[DEV-022](../tasks/DEV-022-rag-conversation.md)
- 继承：[ADR 0002](0002-ai-gateway-and-application-managed-conversations.md)、[ADR 0005](0005-bound-processing-replays-and-retrieval.md)、ADR 0007（接受依据和实现仍在前置 #36）。
- 接受依据：2026-09-29 所有者明确选择“接受全部提议，允许 DEV-022 从 #37 最新 head 创建独立依赖分支；#36/#37 暂不合并”。接受全部接口、11/12 分钟截止与租约、上下文、历史引用保留及 1000/10000/100000 新记录额度。付费、生产启用和前置合并不在授权中。

## 背景

#36/#37 分别实现索引和检索，尚未合并。现有项目聊天的默认两分钟租约小于一次本地 Embedding 的 300 秒上限，
直接把检索拼到普通聊天流程会被另一入口提前抢占。普通聊天幂等键也必须区分 RAG 模式，
而模型生成的文件名、版本和位置不能作为可信引用。

## 决策

conversation 调 knowledge 的公开检索/资格边界和统一 AiGateway；不跨 Mapper。
新增独立、默认关闭的 RAG 入口与 project-rag-v1，普通聊天模板不变。
一个 UUID 对应一次规范化内容、模式、检索和聊天尝试；合法重放不触发任何外部调用，模式/内容冲突明确拒绝。

先持久化绝对截止/请求模式，再执行一次检索和一次 Chat Gateway；全部网络位于事务外。
提议 RAG 总截止 11 分钟、租约 12 分钟；各入口统一按持久截止判断已有生成，普通聊天新请求仍用原上限。
最多 5 个来源，继承检索的完整归属/来源过滤、资格刷新及 100/200/3 预算；空/不完整结果不回退普通聊天。
发送前与发布时经 knowledge 重新校验；最后校验须与会话发布共享项目锁和短事务，来源变化明确失败。

project-rag-v1 把全部片段/项目/历史视作 JSON 编码的不可信数据，不声明工具。
总输入最多 24000 code points/96 KiB UTF-8，检索块最多 8000 code points；只按确定性规则整片移除与裁剪最旧历史。
模型只提供有界 answer 与 C1–C5 citationIds；严格校验后，来源版本、位置和摘要由服务端构造。
保存最小引用快照及真实 usage，禁止保存完整检索 prompt、向量、原始模型 JSON 或隐藏推理。

引用定位不依赖可删除的源资源 FK。成功重放不重生成；旧来源不可用时只标记 unavailable，
不读退役正文，也不保证删除原文档能撤回已保存的历史回答摘要。
提议最多 5 引用/调用、1000 RAG 调用/对话、10000/项目、100000/全局，按最多 5 KiB 元数据/调用原子占额；
失败/未知/软删除仍占额，既有重放优先，满额不新建失败记录。长期历史没有自动清账 TTL，
后续明确会话删除/保留策略才能释放；这些新限额已由所有者明确接受。

## 后果与限制

增加状态、来源快照、统一租约检查与原子记录额度；允许因没有依据、来源竞争或预算限制明确失败，
不能承诺所有问题都回答，也不能由 Schema 合规证明事实正确。
需新 migration 及旧聊天兼容测试，不能复用普通聊天的两分钟恢复判定。

接口、总截止、新额度、旧数据兼容及历史回答保留语义已接受；实现细节与实测结果见 [API](../api/rag-conversation.md)及[验收记录](../testing/rag-conversation-acceptance.md)。
使用既有 Stub/Mock 和合成输入完成 CI，默认所有调用开关关闭；真实付费聊天及生产启用需另行确认账户和预算。
本 ADR 不批准任何新模型、真实付费测试、部署、前端或自动合并。
