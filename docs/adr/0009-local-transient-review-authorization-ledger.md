# ADR 0009：瞬时评审使用本机事务授权账本

- 状态：Proposed
- 日期：2026-10-13
- 任务：DEV-034，草稿 [#53](https://github.com/RyderChang/DevMate/pull/53)

## 背景

未来新轮真实评审必须独立于 DEV-032 的已用尽额度。发送前确认、单次执行、跨进程互斥和崩溃后的未知预留不能仅由内存状态或调用方布尔声明保证。正文和来源不允许落盘；¥2.00 托管费用上界仍未证明，当前不允许发送。

## 提议

瞬时本机工具使用标准库 SQLite 的 FULL 事务保存闭合授权/预留/usage 元数据，采用本机永久锁文件（Windows msvcrt/POSIX flock）作为轮次排他锁。独立 authorizationId、roundId、题组唯一约束禁止恢复、重复和补额。先完整提交 UNKNOWN 预留，再交接单次请求；任何失败停止并保留次数/预留。此实现只以 OFFLINE_LEDGER_STUB 验证；真实授权类型与 HTTPS 公开入口继续固定拒绝。

账本权威存储必须为一个已审查的本机目录，不能用多目录、多主机或复制文件扩展授权。真实启用前须重新冻结满足费用边界的计划、审查授权交接及所有者环境证据；此 ADR 不批准费用或真实发送。详细合同与验证边界见[驱动和账本说明](../development/claim-citation-https-ledger.md)。

## 后果与替代方案

无需新增数据库服务或依赖，能在 SQLite 提交确认失败或进程崩溃时保留 UNKNOWN。代价是本机单进程串行执行、无续跑/补额，以及要求本地文件系统支持 FULL 提交和文件锁。不承诺物理断电、网络盘或恶意账本改写治理；未来分布式需求必须另行决策。

不继续用普通 JSON 替换及独立凭据文件模拟真实授权，因为多个文件不能原子提交且跨进程恢复难以证明；也不为一次人工本机评审引入生产 MySQL 或分布式锁。原 JSON Stub 工具保留，其离线合同不变。
