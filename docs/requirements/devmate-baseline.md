# DevMate 需求与架构基线

## 产品定位

DevMate 不是通用聊天机器人，而是围绕软件项目上下文、服务真实研发流程的 AI 助手平台。当前处于工程基础建设阶段，本文件描述的是已确认需求与目标架构，不代表功能已经实现。

## MVP 能力范围

MVP 规划提供项目上下文 AI 对话、文档与代码 RAG、GitHub 仓库只读分析、结构化 AI 代码审查，以及 Java/JUnit 测试场景与测试代码生成。首版深度支持 Java/Spring；其他语言仅提供基础文本检索。

GitHub 集成首版只读。系统不会自动修改、执行或合并用户代码；测试生成只负责生成和导出，不在服务端执行未知仓库代码。

## 用户与访问模型

用户角色分为游客、普通用户和管理员。MVP 中，项目默认仅创建者可访问；所有资源操作必须同时校验用户身份与资源归属。

## 目标架构与数据职责

项目采用前后端分离的 monorepo，后端首先采用模块化单体。MySQL 保存业务数据，Redis 承担缓存、限流和任务协调，Qdrant 保存向量，MinIO 保存文件。外部模型通过统一 AI Gateway 接入，业务模块不直接绑定提供商。

第一阶段仅建设工程基座、认证和项目空间，暂不接入 AI 服务。

## 核心非功能要求

- 对项目和知识数据强制执行资源归属校验；
- 服务端安全保存密钥，不向前端、日志或响应泄露；
- 将仓库内容视为不可信输入，防止提示词注入覆盖系统约束；
- 异步任务可重试且保持幂等，并具有明确的状态和上限；
- 对 AI 结构化输出执行 Schema 与业务校验；
- 记录模型、模板版本、来源、Token 用量和执行状态；
- 外部服务可替换为 Stub 或 Mock，确保核心逻辑可测试。

## 七阶段路线图

1. 工程基座、认证与项目空间；
2. AI 对话；
3. RAG 知识库；
4. GitHub 只读分析；
5. AI 代码审查；
6. 测试生成；
7. 管理、可观测性与部署。
