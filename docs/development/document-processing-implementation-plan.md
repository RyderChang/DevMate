## 2. DEV-017 的落地顺序

### 先实现和验证纯文本算法

在 knowledge 内实现无外部依赖的解析器和分块器，使用 JDK 严格 UTF-8 解码。
解析器只去除开头一个 BOM、统一 CRLF/CR 为 LF；Markdown、空白和代码围栏按字面保留。
原字节与规范化文本分别计算 SHA-256。

采用已确认的 `utf8-text-v1` 与 `text-window-v1`，目标 1,000、边界下限 800、硬上限 1,200、重叠 100 个 code point。
保留顺序、区间、行号和每块摘要；规则全文见 DEV-017 第 3、4 节。
使用有界读取、滚动窗口和连续行号/摘要计算，避免为每块重新扫描全文；原文件仍执行 5 MiB 硬限制。
解码器跨缓冲区的 BOM、CRLF 和 supplementary code point 必须有测试。

先用固定合成样本验证全文覆盖、精确重叠、位置一致和重复运行确定性。
不增加 Markdown AST、PDF/DOCX、HTML 渲染或语义分块依赖。

### 再实现持久化与原子发布

新增 Flyway migration，候选结构为处理记录、片段、处理请求映射和项目片段额度；
具体表名、字段、外键与索引在实现 PR 审查，不提前占用 migration 编号。
所有主键沿用 BIGINT 自增。文档记录维护活动处理代引用；不能仅按最新时间选活动代。

推荐流程：

1. 短事务：通过 project 公开服务锁定有效项目，再锁文档；检查归属、`STORED`、幂等和在途任务，
   原子预留 8 MiB，保存 `PENDING` 和冻结策略。
2. 内部扫描器以条件更新领取处理记录，持久化操作版本和租约，转为 `PROCESSING`。
3. 事务外通过已有 `ObjectStorage.read` 受限读取，验证实际长度和原 SHA，执行解析与分块。
   不能从请求接受 bucket/key，也不能将存储接口本身当作授权。
4. 分批写暂存片段。每批短事务均核对项目、文档、处理状态和操作版本，原子将预留转为已用字节；
   删除、租约被重新领取或开关暂停后，旧尝试连暂存写入也必须被拒绝。
5. 最后短事务校验完整块清单、摘要、策略、项目与文档状态，切换活动处理代并提交 `CHUNKED`。
   片段读取只取完整活动代；发布失败不替换仍有效的旧代。
6. 幂等清理失败或退役暂存，完成后释放额度；重试先清理上次尝试的暂存，再按新操作版本执行。

锁顺序统一为项目、文档、处理记录；项目额度操作受同一项目锁串行化。
处理租约与原文件上传租约独立。远程读取和 CPU 处理不包在数据库事务中。
调度、并发、截止时间与重试采用 DEV-017 已确认值，不另起通用队列。

### 删除交接在首个功能 PR 内完成

DEV-016 的 `DocumentTransactions.completeCleanup` 当前在原文件清理后释放容量并删除父文档。
DEV-017 必须扩展这条路径：父元数据物理删除前检查派生片段和恢复工作已清理，或已有独立、完整的持久交接。
不能仅依赖外键报错、内存事件或异常 catch 来阻止丢失定位。

文档删除及项目软删除与发布互斥，立即取消处理并撤销活动代可见性。
后台数据库清理须覆盖暂存、活动及退役代，旧线程不能在清理后补写。
先写入持久状态，再分批执行清理，最后原子清账；删除与重启恢复是验收条件，不能延期到索引任务。

### 最后接入 API 并完成验收

只增加已确认的 POST 处理触发与 GET 处理状态端点；使用统一响应、请求 UUID、JWT 与项目/文档归属校验。
GET 区分最近一次处理结果与仍有效活动代，不返回正文。上传不自动触发处理，处理开关默认关闭。

完整验证顺序：算法单元测试、MockMvc、MySQL 8 Testcontainers、MinIO 有界读取合同、
确定性删除/发布/重领竞态、既有业务回归、Foundation CI。
预期运行 Maven Wrapper 的 `clean verify`，但仅实际执行后才能登记结果。
最关键的完成证据是：重启可恢复、部分片段不可见、跨归属不可读、删除后旧任务不能发布或补写。

## 3. 索引配置参考与国内接入方向

2026-09-28 所有者明确指出主要使用者面向中国市场，并选择先试用 DeepSeek 官方 API。
聊天通过独立 DeepSeek Gateway 适配器接入，不要求购买 OpenAI API；解析与分块仍与模型无关。
[DeepSeek 官方文档](https://api-docs.deepseek.com/)列出了对话接口；截至本次核查未找到官方 Embedding 契约，
不能把对话输出当作向量，也不能把聊天兼容接口等同于 Embedding 可用。
索引提供商改为在独立任务中优先核验国内可用服务或本地模型，模型、维度、tokenizer 与费用随规格单独确定。

以下 OpenAI small 配置保留为可比较的备选参考，不是默认供应商或继续开发的前置条件；
6,000 tokens 与 `cl100k_base` 只适用于该参考规格，不能照搬给 DeepSeek 或未来国内 Embedding 模型。

先用单一模型与规格，减少路由、迁移和成本判断的变量；不复用当前聊天模型及其输出 token 配置。
当前 `AiGateway` 只有 chat 能力，`AI_MAX_OUTPUT_TOKENS` 是聊天输出限制，不能作为 Embedding 输入上限。

| 项目           | OpenAI 备选参考配置                                                                |
| -------------- | ---------------------------------------------------------------------------------- |
| 提供商与模型   | OpenAI `text-embedding-3-small`                                                    |
| 向量维度       | 1,536；请求显式固定并校验输出维度                                                  |
| 距离规则       | Cosine；collection 按 Embedding 规格隔离                                           |
| Token 编码     | `cl100k_base`；精确计数普通文本，特殊标记按用户字面内容处理                        |
| 应用单片段上限 | 6,000 输入 tokens；不得用字符数乘系数替代计数                                      |
| 单次请求       | 最多 32 个片段且合计最多 16,000 tokens，满足任一上限即切批                         |
| 实例并发       | 最多 2 个远程请求，并结合账户实际 rate limit 收紧                                  |
| 超时与重试     | 连接 5 秒、远程总操作 30 秒；明确暂时限流最多重试 2 次；结果未知不自动重复付费调用 |
| 默认状态       | 索引及付费调用关闭；无密钥也可构建和测试                                           |

这组模型/维度/tokenizer 的技术依据来自
[OpenAI 官方 Embedding 指南](https://developers.openai.com/api/docs/guides/embeddings)：
small 默认 1,536 维，第三代模型使用 `cl100k_base`。
[官方 API 契约](https://developers.openai.com/api/reference/resources/embeddings/methods/create)
规定单输入最多 8,192 tokens、单请求合计最多 300,000 tokens。
6,000、32 和 16,000 是应用保护参数，不是提供商限制，也不是已经验证的吞吐结论。

超限、空白块或编码计数异常在调用前明确失败，保留原片段且不发布部分索引；
不截断、不静默丢块、不在索引层暗中生成另一套片段编号。
若后续确需不同分块，应创建新的处理策略与处理代。

模型规格至少包含提供商、请求模型 ID、回执模型 ID、维度、距离、tokenizer 及本地规格修订。
官方 small 模型页面未列出带日期的独立快照，不能虚构不可变远端版本；
本地规格版本与校验样本用于追踪，不承诺提供商内部模型永远不变。
首版不自动升级模型或在 small/large 之间切换。

新增独立的 Embedding Gateway 能力及配置，HTTP 适配器只位于 ai 的 infrastructure。
优先沿用现有 JDK HTTP/JSON 基础设施；tokenizer 实现、词表、许可证、精确依赖版本与摘要在索引准备时锁定，
用官方 tokenizer 生成的中英文、代码、Unicode 和特殊标记 fixture 验证一致性；CI 运行时不下载词表。
Qdrant 通过 knowledge 基础设施接口适配，镜像/API/客户端版本先做隔离核验再锁定，不使用浮动 latest。

## 4. 费用按用量和预算实施

截至 2026-09-28，
[OpenAI 官方 small 模型页面](https://developers.openai.com/api/docs/models/text-embedding-3-small)
列价为每百万输入 tokens **$0.02**。
按此单价：10 万输入 tokens 为 $0.002，100 万为 $0.02。
这仅是模型输入费用示例，不包含税费、网络、MySQL、对象存储、Qdrant、聊天生成或未知重试。
不能按文件 MB 或字符数直接推算实际账单；重叠片段、重建和后续查询均需要分别计数。

首版建议硬上限：每次索引工作 $0.25、每项目每日 $1、部署全局每日 $5，日界线使用 UTC。
预算是上限，不是已花费金额；本次不调用付费接口。
硬上限按已配置的价格版本计算，不替代提供商真实账单；价格过期或配置缺失时暂停付费调用。

预算实现使用 MySQL 原子预留与固定精度金额，禁止浮点累计：

1. 调用前精确计算本批输入 tokens，记录冻结价格、预估金额、工作/批次/尝试标识；
   同时检查工作、项目和全局额度，任何一项不足均不发送请求。
2. 每次新的付费尝试单独预留，历史成功用量与未知结果均占额度；不能把请求 UUID 当作提供商免费重放保证。
3. 成功后按响应 usage 对账。usage 缺失、数量不符或高于预留时暂停后续调用并保留审计依据，不能当作零消耗。
4. 请求可能已发送但结果未知时，保留保守占用并转受控恢复，不自动退款或立即重新 Embedding。
   后续人工对账/重试仍受剩余预算限制。
5. 明确限流可按 Retry-After 有界等待后重试；额度耗尽、认证或参数错误不重试。
   数据库暂时不可写时，依靠已存在的预留恢复，不允许绕过预算发请求。

模型结果通过数量、索引位置、维度、有限数值和非零范数检查后才能交给向量适配器。
用量记录保存归属、模型规格、批次、tokens、价格版本、耗时和安全状态，不保存正文或原始请求响应。
此处先针对索引工作建账；以后查询 Embedding 复用预算边界，并在检索任务中增加查询限额。

## 5. 向量发布、恢复与质量验收

MySQL 保存索引工作、冻结处理代、批清单、点定位、规格、远程操作状态和清理依据。
Qdrant 仅保存向量及必要来源字段；正文从经过授权的 knowledge 内部服务读取。
点身份包含文档、处理代、索引代、块序号和规格摘要，重复 upsert 幂等；独立代不覆盖。

每批先写持久操作记录，再执行事务外调用；验证整代向量完整且处理代仍有效后，原子发布 `INDEXED`。
删除与换代先撤销可检索资格，再清理；未知远端写入保留操作定位和退役代，不能以租约到期证明写入结束。
后续检索既强制用户/项目向量过滤，也通过 MySQL 再核对活动代和删除状态。

索引任务验收使用模型 Stub、HTTP 合同 Stub、真实隔离 Qdrant/MySQL，覆盖预算并发、
重复请求、错误维度/NaN/缺块、崩溃恢复、响应丢失、部分 upsert、删除后迟到写入与跨归属命中。
CI 不调用真实付费模型，不把 Stub 检索结果当作模型质量结论。

启用试点后，用经授权的非敏感样本建立中英文技术文档、Java/Spring 术语和相近但不同答案的检索集，
记录 Recall@5、MRR、费用和耗时，作为是否改用其他模型的证据。
评测和改模型均属于索引/检索任务，不使用公开榜单代替 DevMate 自身验证。
