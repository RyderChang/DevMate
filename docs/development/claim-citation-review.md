# 正文不落盘的逐断言引用核验流程

日期：2026-10-11；离线调用适配更新于 2026-10-12。规范版本 `claim-review-v1`；任务见 [DEV-034](../tasks/DEV-034-claim-citation-review.md)，当前材料审查见[验收记录](../testing/claim-citation-review-acceptance.md)。已实现[离线全断言窗口、凭据校验器及 Stub 调用适配](../../scripts/rag-claim-review/README.md)，并用合成数据验证。**没有重新生成 DEV-032 答案，HTTP 真实传输和新轮付费授权均未接入；离线信封驱动及[冻结计划](claim-citation-new-round-plan.md)已准备**。

## 评审对象与独立维度

每份回答以自己的题号、组别、来源快照为边界；`C1` 不能跨题或跨组使用。冻结七份公开来源、题目与 E1–E17 核心要求，核对文件 SHA、片段 SHA 及行区间。历史 DEV-032 使用原五个候选；采用 PR #51 候选的新样本必须另立轮次，不能与原样本混记。

| 维度             | 要回答的问题                                                   | 不足以证明该维度的材料                         |
| ---------------- | -------------------------------------------------------------- | ---------------------------------------------- |
| 核心覆盖         | 问题要求的每个核心事实是否实际出现，前提、范围和时点是否正确？ | 来源中存在 E 槽，或只答对一个核心结论          |
| 事实支持         | 整个冻结资料是否支持每个原子断言，包括额外事实？               | 结构成功、合法 ID、关键词匹配                  |
| 直接来源覆盖     | 返回来源是否按同一 SHA 完整覆盖要求的直接证据行？              | 正确推断、间接背景、别的文件中的证据           |
| 引用对应         | 该断言实际引用的片段是否支持它？                               | 未被引用的校核证据、末尾列出的来源集合         |
| 就近绑定         | 是否可以明确把这处引用绑定到该断言？                           | 全文出现一次 `[C1]`，或核心 E 槽的标记交集非空 |
| 完整性与引用精度 | 是否漏核额外断言、遗漏题意或加入无关引用？                     | 17 个核心槽全支持，或引用数达到五个            |

整体语义支持可以与缺少直接来源并存；就近标记可以与引用内容不支持并存。这些组合分别保留，不能互相覆盖。

## 正文的取得与应用层边界

1. 仅在另行授权的实验调用返回时，把经过现有网关及输出校验的答案、该次返回引用映射、实际发送候选和冻结证据留在内存。先保存 usage/固定状态与未知评审项，再打开本机窗口；不为人工评审再调用任何模型。
2. 窗口只供人阅读和选择固定判定；没有自由文本备注、导出、复制或截图功能。不把答案传到终端、Codex 对话、命令参数、临时文件、HTML 页面、浏览器存储或模型评审服务。禁用会捕获响应/请求正文的调试日志；异常只输出固定错误码，禁止 traceback 带局部正文。
3. 应用层不写正文、完整提示词或证据摘录；也不创建崩溃转储。该约束不等于承诺操作系统不会换页、第三方录屏或终端环境不会截屏；不能把文档流程描述成操作系统级保密验证。若运行环境会自动保存窗口或内存内容，先解决该环境问题，不进入真实评审。
4. 结构失败不强行抽取正文进行语义评审，保留固定失败类别及未评审状态；网络未知立即停止，保留次数/费用预留，不自动重试、恢复续跑或沿用耗尽授权。
5. 关闭窗口或捕获的中断时，未提交的断言记录全部作废，已保存 usage/来源元数据仍在；成功保存时评审状态记 `INTERRUPTED`，不把局部选择计为完成。进程被强制终止或保存失败可能只留下先前的未知凭据，仍不能计作完成或自动续跑。提交后清理窗口和正文引用、结束进程。清理对象不保证物理内存安全擦除。

当前离线适配先排他创建 `OFFLINE_STUB` round 文件，再持久化该次 `UNKNOWN` 次数/费用预留与未知凭据，最后发送一次内存 Stub。相同内存 Ticket 身份与全部题组/scope/候选字段比对通过后保存 usage；生产 JSON 通过捕获的管道交给现有 Java 校验器，实际返回 C 及 source/chunk SHA、ordinal、字符与行定位和类型精确匹配后才开窗口。合法 usage 在结构/定位失败时保留，跨请求响应不归账。失败保留预留，未知/中断/保存失败停止，禁止重发同题组或恢复同 round。模拟费率与授权不提供真实付费能力；固定八类生产结构错误不由 Python 重写或降级处理。详情见工具说明。

这个流程适用于有瞬时正文的新轮。DEV-032 已完成的调用没有保存正文，不能从脱敏结果、请求哈希、token 数、源片段或下一次模型输出恢复原回答。不得去搜索密钥、日志、浏览器缓存或提供商账户以猜测重建。

## 从整份回答拆分原子断言

评审者先通读全文，再按出现顺序分配 `A1`、`A2` 等本地编号，记录半开字符区间 `[start,end)`，采用 Python Unicode 字符索引。同一句包含两个可以独立真假的事实时拆成两项；同一断言可含多个不连续区间，以保留限定词、指代和前提。重复出现的事实单独登记，后文正确表述不能抵消前文矛盾。

把断言映射到一个或多个 E 槽，分类 `CORE` 或 `EXTRA`；Q10 的资料不足声明分类 `ABSTENTION`。没有事实内容的问候、标题或格式语句不计事实，但必须完成全文第二遍检查，防止遗漏数字、例外、因果、否定、状态和背景陈述。对每个预期核心槽另外记录 `PRESENT` / `OMITTED` / `UNKNOWN`；遗漏不虚构成一个答案断言。

“默认关闭”须保留具体功能范围；“未证明生产已启用”不能被拆成“生产未启用”。“未调用本次索引”不能自动推出“从未有合格旧活动代”。“没有相关机制”的全称否定必须限定检索的冻结资料范围。含混指代无法消解时记资料不足；出现历史/当前冲突时保留时点，不能任取支持片段。

Q10 的正确弃答与后续额外事实分别评审。不能把检索上限、扫描点数、未启用某功能或目录状态推成实际生产总量，也不能因弃答通过而放过额外事实。

## 逐断言评判与引用绑定

对每项先阅读完整冻结证据，再逐一阅读答案在该处关联的返回引用区间。支持判定 `SUPPORTED` / `CONTRADICTED` / `INSUFFICIENT` / `CONFLICTING` / `UNKNOWN` 由人工给出；同时记录支持类型 `DIRECT` / `INFERENCE` / `NONE` / `UNKNOWN`。合理推断必须有明确前提；它不能满足任务指定的直接证据覆盖要求。冻结资料外的实际部署或账户状态不臆测。

对每个“断言—引用”对独立记录对应判定 `SUPPORTS` / `CONTRADICTS` / `INSUFFICIENT` / `IRRELEVANT` / `UNKNOWN` 和上述支持类型。片段只支持半句时拆断言或记不足；同一片段分别支持多个断言可以复用编号，但每个对应关系都要评审。冻结资料中另有直接证据而实际引用没有时，保存为独立校核来源，不能挪入答案的引用对应结果。

就近绑定不设字符距离自动分数，由人核对语法和布局：

| 判定          | 人工口径                                                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `LOCAL`       | 同句/同一列表项的标记明确指向该断言；紧邻下一句也须指向明确且没有插入其他事实。连续复合句尾的共享标记只有作用域清楚时才能绑定所有相关断言。 |
| `GLOBAL_ONLY` | 只有来源列表或全文末尾编号集合，无法给该断言一个局部对应。                                                                                  |
| `ABSENT`      | 已阅读正文，断言没有引用关联，且没有可用的全局来源列表。                                                                                    |
| `AMBIGUOUS`   | 有标记，但多个事实、代词或列表结构使指向不明确。                                                                                            |
| `UNKNOWN`     | 没有正文、未评审、中断，或无法判断标记位置。                                                                                                |

`LOCAL` 只描述位置与指向；只有该对 `SUPPORTS` 且满足要求的证据类型时，才算一项充分的局部引用。当前产品允许只返回引用列表，因此 `GLOBAL_ONLY` 是独立质量缺口，不能冒称生产结构校验失败。

另对每个返回 `C1`–`C5` 记录是否用于任何断言及其相关性；无关来源单列，不能因为某个合法 ID 在答案末尾出现就计作充分引用。全文扫描结束后才标记断言清单完整；不存在正文时断言总数应为 `null`，不能记零。

## 可保存的脱敏评审凭据

实现逐字段构造并拒绝未知键；以下是白名单规范，实际 `review.py` 凭据使用数字题号、生成的本地 sampleId、`FROZEN` / `SYNTHETIC` / `OFFLINE_STUB` 模式及固定 reviewer 类型。`OFFLINE_STUB` 的公开来源仍按原 manifest 校验，但其回答/usage 与评审者选择均为合成，完成时固定标为 `SYNTHETIC_CHOICES`，不能计为真实输出。所有其他字符串只能来自固定版本、组别、枚举、规范化 `E1`–`E17`、`C1`–`C5`、`S1`–`S7` 和按序生成的 `A` 编号。来源路径通过 S 编号查冻结表，不接受模型给的任意路径/文件名。

| 层级         | 允许保存的信息                                                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 轮次/样本    | 规范版本、受控本地轮次编号、题号/组别、冻结 scope SHA、结构状态、人工评审状态 `NOT_REVIEWED` / `INTERRUPTED` / `COMPLETED`、固定 reviewer 类型 |
| 整份回答     | 已核验断言数或 `null`、全文清单完整标记、各核心槽出现/遗漏、独立弃答判定、按固定枚举统计的结果                                                 |
| 每项断言     | 本地 A 编号、字符区间、CORE/EXTRA/ABSTENTION、对应 E 编号、事实支持及类型、校核 S 编号/source SHA/证据行区间；校核可在候选之外                 |
| 每项引用关系 | C 编号、片段 SHA/定位、对应判定及类型、就近绑定枚举、人工选定标记的数字区间或 `null`                                                           |
| 每项来源     | 是否用于已登记断言、相关性判定；只存规范化来源定位，不存摘录                                                                                   |

禁止保存断言原文、人工改写摘要、理由自由文本、答案/来源摘录、完整提示词、原始错误体、任意 URL 或模型生成的 ID；也不把正文放入哈希字段再当作可恢复索引。SHA 只允许与冻结 source/chunk/scope 表匹配。长度、序号、区间、行数须限定范围和类型，布尔不能冒充整数；C 必须属于该样本的返回来源，证据行必须落在冻结源内。标记位置只用于对应，不允许从位置自动推断语义。

这份凭据能保留判定与定位，**不能让另一位评审者在正文销毁后独立复核原断言**。如需双人核验，应在同一内存窗口关闭前分别提交选择并记录分歧；不得保存正文解决复核需求。未完成第二遍全文检查或有待审项时不能置 `COMPLETED`；完整评审可以有矛盾或不足，`COMPLETED` 不等于质量通过。

## 实现前的离线验证门槛

继续阶段已用合成回答与人工选择 Stub 完成以下记录/窗口验证，实际结果见验收记录。这些测试验证判定保留与安全边界，不证明自动语义评分或真实答案质量：

- 答案、来源、非法 ID 和异常包含哨兵正文；序列化记录、终端、日志与临时目录均不得出现哨兵。拒绝任意备注、文件名、URL、非法枚举及越界区间，错误不回显输入。
- 同一句两个事实、重复矛盾、时点冲突、前提省略、核心遗漏、正确弃答夹带无依据额外事实，均被独立登记。
- 无内联但来源覆盖、全文有标记但局部未绑定、局部引用不支持、直接证据仅在校核源、多余引用、同一 C 跨题误用，均维持分项结果。
- 提交、关闭、中断、保存失败及结构失败路径不会把未审项计为通过，不重发请求；原始 usage 与预留不丢失。

离线测试通过后再冻结新轮输入、次数与费用及外发范围。需要新模型输出时必须另获授权；不复用 DEV-032 额度。最终报告同时列尝试数、结构失败数、完整评审样本数、核心遗漏与未知数、核心/额外断言的支持与对应/绑定分母、无关引用和弃答。任何分母缺失、未知或中断都不能解释为全题通过；不由该流程自动形成生产输出约束采纳决策。
