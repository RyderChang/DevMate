**完整回答**：

```text
两个问题的结论都可以从现有资料直接得到，但它们涉及两个不同含义的"有效性"，需要区分。

**1. checkedAt 不会随每次读取而更新。** `rag.checkedAt` 记录的是原回答发布时的资格检查时刻（UTC ISO 8601），该时间用于记录原回答的发布资格，重放时"不会伪装为新的生成或更新该时间"（C1）。历史读取接口的说明更直接："`rag.checkedAt` 是原发布时刻，不随历史读取刷新"（C2）。因此每次读取历史消息时返回的 checkedAt 是同一个固定的旧时间，不会因为被再次读取而被刷新为当前时间。注意这里存在一个容易被误读的对照：同一个 history 响应中，引用项的 `available` 是"根据当前活动来源重新核验"的，删除或换代后变为 `false`，历史定位仍保留（C2）；前端验收记录也说明历史 GET 的 evidence 只是只读映射成功 RAG 助手消息保存的摘要与引用，"当前可用性按完整来源定位和项目归属批量核验"（C3）。也就是说，读取时会重新核验的是 available，而不是 checkedAt——这两者的时效语义相反，不能混为一谈。

**2. available=true 不能证明答案事实已经人工核实。** 资料中没有任何关于"人工核实"的机制、字段或流程描述，因此无法支持这一推论，也无法从现有证据中否认它——该问题超出了这些文档所覆盖的范围。就文档能证明的内容而言，available 表达的是**来源可用性与归属校验结果**：它由服务端授权快照构造的来源定位信息决定，并且读取时按当前活动来源重新核验（C1、C2）。换句话说，available=true 说明相关来源当前仍存在、仍属于该项目、定位信息仍可解析且引用被列为可用，属于来源层面的技术性资格，而不是对回答内容事实正确性的人工背书。文档中也没有为引用返回引用正文、模型编造的定位或置信度（C1），这进一步说明 available 不是事实可信度的度量。

另一个相关但不同的概念是发布时的来源资格检查：发送前和发布时都会重新验证全部实际提供的来源，来源变化、过期或坏输出不会发布助手消息（C2），失败时按稳定错误返回，例如 RAG_SOURCE_CHANGED（409，"Document sources are no longer eligible"）（C4）。这些机制保证的是"发布时来源合格、答案取自经校验的模型 JSON 且引用编号合法"（模型仅提供严格 JSON answer 和 citationIds，拒绝无引用回答及未列入 citationIds 的内联编号，C2、C4），仍然不等于人工事实核实。

综合来看：checkedAt 是冻结的历史发布时刻，读取时不会刷新；而 available 会在读取时依据当前来源重新核验，它的含义是来源仍可用，不能延伸解读为答案事实已获人工核实。资料未定义任何人工核实标志，故对"能否证明人工核实"只能给出否定性结论：没有证据支持，现有字段也不承担该语义（C1、C2、C3、C4）。
```

**完整回答**：

```text
合法 RAG 重放会返回原已保存的助手消息/历史回答与引用摘要，而不会重新生成回答或重新检索来源。

具体处理方式：

1. **重放命中已保存结果**：合法 RAG 重放先于额度检查执行，直接返回原已保存消息、usage 与引用；不会检索、不占新的 Embedding 额度、也不会调用聊天模型（C2）。重放时 `rag.checkedAt` 仍是原回答发布资格检查的时刻，不会伪装成新的生成时间或更新该时间（C1）。

2. **历史回答仍返回**：源文档删除或换代后，成功重放仍返回历史回答和“最小定位”，但对应引用项的 `available=false`，并且不读取退役来源的正文（C2）。历史读取时 `citations[].available` 会根据当前活动来源重新核验，删除或换代后为 `false`，但历史定位仍保留（C2）。因此历史 answer 与定位不会被撤回，变的是引用可用性标记，而不是历史正文的重写。

3. **引用内容与来源正文**：citations 最多 5 项，按 citationId 排序，每项包含 citationId、source 与 available；source 由服务端授权快照构造，包括 pointId、documentId、filename、processingId、indexId、各 generation、parserVersion、strategyVersion、sourceSha256、chunkSha256、ordinal、start/end、startLine/endLine 等定位字段（C1）。响应不返回引用正文、模型编造的定位或置信度（C1）；历史读取也不返回来源正文（C2）。因此在来源退役后，保留下来的仍是历史回答和最小定位/引用元数据，不是重新读取到的来源正文。
```

## 结论与限制

五个真实 RAG POST 均为 HTTP 200 / `SUCCEEDED`，且有服务端结构化引用；输入 21,945、输出 2,753，合计 24,698 tokens。所有者报告的提供商账单为人民币 0.06 元，低于授权的人民币 5 元上限。五题的**核心结论**与冻结资料一致，包括对未知生产堆值的弃答；这不是通用准确率或召回率。逐断言核对发现：案例 2 关于人工核实的代词指向含混，且未引用同一资料第 28 行的直接提示，不能确定为事实错误。案例 4 对“已实现”的候选引用偏合同性、对生产状态说得过满，并遗漏了早期基线与当前 README 的主要时点冲突。案例 5 的正确弃答夹带了未受证据支持的“因此不可能”推论。

本次只核对实际返回的五个回答与其**已返回引用**，不计算检索召回率，也没有执行来源删除后的重放、生产部署或界面验收。后续[独立检索复跑](real-rag-retrieval-evaluation.md)记录了同源五题的完整 top‑5 候选和关键证据位置覆盖，不能代替本次未保存的候选。`available=true`、合法引用编号、成功状态、token usage 都不能代替逐项事实核查。请求模型 ID 与实际 token 用量来自 DevMate 的 invocation 摘要；提供商内部模型版本和账单页面未独立取得，人民币 0.06 元金额来自所有者报告。
