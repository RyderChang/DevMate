## 基线与目标

DEV-020、DEV-021、DEV-022 已合并至 `develop`，基线 SHA `f3d6e5b7b63e8b51d9fe5cdd711a2bded0b6b11f`。
本任务在独立 `feature/dev-023-frontend-rag-citations` 分支补齐历史消息引用，并在项目对话页提供显式的文档问答入口。
入口默认关闭；后端 JWT、项目归属、RAG 开关和资源上限仍是权威判断。

## 范围与合同

- 历史消息 GET 在原五个字段外增加 `evidence`；仅成功 RAG 的助手消息返回 `{rag,citations}`，普通聊天和用户消息为 `null`。普通聊天及 RAG 的 POST 成功响应保持原结构。
- 历史页最多 100 条、最多 500 条引用。按当前 owner/project、活动来源及完整定位批量核验 `available`；不读取退役片段正文，不调用检索、Embedding 或聊天模型。`checkedAt` 保留原发布时刻。删除或换代后保留历史引用定位并标为不可用；父项目删除仍为 404。
- 前端 `VITE_RAG_ENABLED=false` 控制模式入口，默认普通聊天；显式文档问答只调用 `/rag-messages`，失败不自动回退普通聊天。两种模式的 UUID、内容和模式在单次提交后冻结；未知结果仅由用户手动以同一三元组确认，最多三次尝试。
- 普通聊天保留 130 秒请求超时；RAG 使用 690 秒请求超时。RAG 内容按完整 Unicode、strip 后非空与最多 8000 UTF-16 码元预校验；服务器继续实施 token 与资源边界。
- 引用只以纯文本显示服务端可信定位、行号及当前可用性；明确提示“引用定位不代表回答事实已经人工确认”。不生成源文件 URL，不解析模型 HTML。
