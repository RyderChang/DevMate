## 2. 当前基线与启动条件

编写本任务书时，仓库位于 `feature/dev-010-frontend-authentication`，DEV-010 已实现前端注册、登录、会话恢复、统一 HTTP 客户端、受保护路由和退出登录，但尚未合并到 `develop`。DEV-009 已在后端提供按当前用户隔离的项目 CRUD API。

DEV-011 开始实现前必须满足以下条件：

1. DEV-010 已通过项目所有者审核并合并到 `develop`；
2. 从最新 `develop` 创建独立分支 `feature/dev-011-frontend-project-workspace`；
3. DEV-009 的五个项目端点及响应结构未发生未同步的契约变化；
4. 前端认证回归测试保持通过。

不得直接在 DEV-010 的功能分支继续实现 DEV-011，也不得为了前端页面调整已发布的 V1 至 V4 migration。

## 3. 背景与目标

当前用户登录后只能看到认证闭环的占位首页，尚不能管理自己的项目。DEV-011 在现有认证、路由保护和项目后端 API 之上建立第一阶段所需的前端项目空间闭环：

1. 登录用户进入应用后看到自己的项目列表；
2. 用户可以分页浏览项目，并区分加载、空数据、失败和成功状态；
3. 用户可以创建项目并进入项目详情；
4. 用户可以查看和编辑项目名称、描述及时间信息；
5. 用户可以在明确确认后删除项目；
6. 项目不存在、已删除或不属于当前用户时，前端使用统一的不可用语义，不泄露资源存在性；
7. 所有请求复用 DEV-010 的 Axios 实例、Bearer Token 和 `401` 会话失效处理；
8. API 封装、路由和关键页面交互具有自动化测试。

本任务完成后，第一阶段的后端和前端主流程具备可用闭环，但不代表 AI 对话、知识库或 GitHub 集成已经开始实现。

## 4. 冻结的设计决策

### 4.1 路由与导航

受保护区域使用以下路由：

| 路径                        | 路由名           | 用途                 |
| --------------------------- | ---------------- | -------------------- |
| `/`                         | `home`           | 重定向到 `/projects` |
| `/projects`                 | `project-list`   | 项目列表             |
| `/projects/new`             | `project-create` | 创建项目             |
| `/projects/:projectId`      | `project-detail` | 项目详情             |
| `/projects/:projectId/edit` | `project-edit`   | 编辑项目             |

要求：

- 所有项目路由都位于现有受保护布局下，并继续由 `requiresAuth` 守卫保护；
- `/projects/new` 必须作为静态路由正确匹配，不能被 `:projectId` 吞掉；
- 登录后的默认落点改为项目列表；DEV-010 的安全站内 `redirect` 行为保持有效；
- 布局提供清晰的“项目”导航和当前用户、退出入口；
- 项目业务页面可以使用路由懒加载，避免新页面全部进入首屏同步模块；
- 非法、非正整数或超过 JavaScript 安全整数范围的 `projectId` 不发送 API 请求，页面按项目不可用状态处理；
- 本任务不建立全站通用 404 页面，也不引入面包屑、标签页缓存或复杂侧边栏系统。

### 4.2 后端 API 契约

前端只消费 DEV-009 已有接口，不修改服务端：

| 方法     | 路径                           | 请求                     | 成功数据              |
| -------- | ------------------------------ | ------------------------ | --------------------- |
| `GET`    | `/projects?page=1&pageSize=20` | 查询参数                 | `PageResult<Project>` |
| `POST`   | `/projects`                    | `ProjectMutationRequest` | `Project`             |
| `GET`    | `/projects/{projectId}`        | 路径参数                 | `Project`             |
| `PUT`    | `/projects/{projectId}`        | `ProjectMutationRequest` | `Project`             |
| `DELETE` | `/projects/{projectId}`        | 无                       | `null`                |

统一响应仍为：

```ts
interface ApiResult<T> {
  code: number;
  message: string;
  data: T;
}
```

项目类型与分页类型按实际响应定义：

```ts
interface Project {
  id: number;
  name: string;
  description: string | null;
  createTime: string;
  updateTime: string;
}

interface ProjectMutationRequest {
  name: string;
  description?: string | null;
}

interface PageResult<T> {
  page: number;
  pageSize: number;
  total: number;
  items: T[];
}
```

前端不得发送或伪造 `ownerUserId`、`deleted`、`createTime`、`updateTime` 等服务端管理字段。不得依据前端缓存推断项目归属；后端仍是所有权校验的唯一权威来源。

### 4.3 分页与 URL 状态

- 默认 `page=1`、`pageSize=20`；
- 可选页大小限制在 `10`、`20`、`50`、`100`，不超过后端上限 100；
- 页码和页大小写入 URL 查询参数，使刷新和浏览器前进、后退可以恢复列表位置；
- 缺失的查询参数使用默认值；非法值在发起请求前规范化，并通过路由替换为合法 URL；
- 修改页大小时返回第 1 页；
- 删除当前页最后一项且当前页大于 1 时，回到前一页并重新加载；其他成功删除在当前页重新加载；
- 列表顺序完全使用后端的 `updateTime DESC, id DESC` 结果，前端不另行排序；
- 本任务不实现搜索、筛选、无限滚动、用户自定义排序或本地离线缓存。

### 4.4 表单与输入规范化

创建和编辑复用同一组表单规则：

- 项目名称必填，提交前去除首尾空白，规范化后长度为 1 至 100 个字符；
- 项目描述可选，提交前去除首尾空白，最大 1000 个字符；
- 空白描述提交为 `null` 或空字符串，由现有后端统一规范化为 `null`；
- 表单展示当前字符数，提交中禁用重复提交；
- 前端校验用于即时反馈，后端校验仍是权威结果；
- 服务端返回的安全 `4xx` 消息可以展示，网络错误和 `5xx` 使用统一通用提示；
- 不将表单内容、响应体或 Bearer Token 写入日志。

### 4.5 页面交互

项目列表页必须提供：

- 加载骨架或加载状态；
- 首次加载失败提示和重试入口；
- 无项目时的空状态和创建入口；
- 有数据时的项目名称、描述摘要、更新时间以及查看、编辑、删除操作；
- 分页器和总数；
- 删除确认、删除中状态、成功反馈和失败恢复。

项目详情页必须提供：

- 独立加载、失败重试和项目不可用状态；
- 完整名称、描述、创建时间和更新时间；
- 返回列表、编辑和删除入口；
- 删除成功后返回项目列表。

创建页成功后进入新项目详情；编辑页先读取服务端最新项目，成功后进入详情。用户取消创建或编辑时返回合理的上一路径，不自动保存草稿。

删除必须使用明确的二次确认，确认文案包含项目名称。取消删除不得调用 API。不得使用前端“隐藏按钮”代替后端所有权校验。

### 4.6 时间与内容展示

- `createTime` 和 `updateTime` 按 ISO 8601 字符串接收；
- 使用浏览器本地时区和稳定的日期格式展示，解析失败时显示 `--`，页面不能崩溃；
- 项目名称和描述只使用 Vue 文本插值或等效安全文本渲染；
- 禁止使用 `v-html` 渲染项目内容；
- 长名称和长描述在窄屏下必须换行或截断，不得破坏布局；
- 页面至少在 320px 宽度下保持可操作，关键操作具有可理解的按钮文字或无障碍标签。

### 4.7 状态管理边界

项目 API 集中放在 `src/api/`。列表、详情和表单的加载、错误、分页、确认框等页面局部状态保留在组件或领域 composable 中；只有确实需要跨项目页面共享且能定义失效规则的状态才进入 Pinia。

不得把后端项目数据长期持久化到 `localStorage` 或 `sessionStorage`。切换账号或收到 `401` 后，不得向新会话展示前一用户的项目快照。

## 5. 实现范围

### 5.1 项目 API 与类型

- 扩展公共 API 类型，增加 `Project`、`ProjectMutationRequest` 和通用 `PageResult<T>`；
- 新增项目 API 模块，封装列表、创建、详情、更新和删除；
- 路径参数必须由已验证的项目 ID 构造；
- 复用现有 Axios 实例和错误消息工具，不创建第二套基础 URL、Token 注入或 `401` 处理。

### 5.2 路由与布局

- 将认证后的默认页面切换为项目列表；
- 注册项目列表、创建、详情和编辑路由；
- 保留登录、注册、会话恢复、安全重定向和退出登录语义；
- 在现有布局中增加最小项目导航，不提前设计 AI、知识库或管理菜单。

### 5.3 项目页面和可复用组件

- 实现项目列表页；
- 实现项目详情页；
- 实现创建和编辑页面；
- 在创建与编辑确有重复时提取项目表单组件；
- 仅在能减少重复且职责清晰时提取分页、日期格式化或请求状态 composable，不为形式创建空抽象。

### 5.4 自动化测试

使用现有 Vitest、Vue Test Utils 和 jsdom，至少覆盖：

- 项目 API 方法、路径、查询参数和请求体；
- 根路径重定向和全部项目路由的认证保护；
- 项目列表加载、成功、空数据、失败与重试；
- 查询参数规范化、翻页和页大小变更；
- 创建表单规范化、校验、重复提交保护和成功跳转；
- 编辑页初始加载、回填、更新请求和成功跳转；
- 详情页成功、失败重试和统一项目不可用状态；
- 删除取消、确认、成功、失败及删除页末最后一项后的页码修正；
- `401` 继续触发现有会话清理和登录跳转；
- 服务端项目内容按文本渲染，不引入不可信 HTML；
- DEV-010 认证 Store、HTTP 拦截器、路由守卫和登录注册页面测试无回归。

测试必须 Mock 项目 API，不依赖真实后端、公共网络、真实账号或固定执行顺序。

## 6. 错误与安全语义

| 场景                    | 前端行为                                                       |
| ----------------------- | -------------------------------------------------------------- |
| `400` 参数错误          | 保留当前表单或列表状态，展示后端安全消息或通用参数提示         |
| `401` 会话失效          | 交由现有拦截器清理会话并跳转登录页                             |
| `403` 权限不足          | 展示无权限提示，不尝试绕过或重放请求                           |
| `404 PROJECT_NOT_FOUND` | 统一展示“项目不存在或无权访问”，不区分不存在、已删除和他人项目 |
| 网络错误                | 展示可重试的网络失败状态，不清空已有有效数据                   |
| `5xx`                   | 展示通用服务异常提示，不暴露响应内部细节                       |

额外要求：

- 不在客户端通过枚举 ID、预取相邻 ID 或缓存响应探测其他用户项目；
- 不吞掉请求失败后假装创建、更新或删除成功；
- 不使用乐观更新掩盖服务端失败；
- 页面卸载后返回的旧请求不得覆盖新页面的可见状态；可通过请求标识、卸载保护或取消请求实现；
- 用户快速重复操作时只允许一个有效的创建、更新或删除请求。

## 7. 非目标

DEV-011 不实现：

- 后端 Controller、Service、Mapper、DTO、VO 或安全配置变更；
- 数据库 migration 或项目字段变更；
- 项目成员、邀请、协作者、团队、组织或所有权转让；
- 管理员跨用户查看或管理项目；
- 项目恢复、回收站、批量删除或物理清理；
- 标签、收藏、封面、模板、搜索、筛选或自定义排序；
- GitHub 仓库绑定、Token、Webhook、同步或代码浏览；
- 文档或文件上传、MinIO、S3、Qdrant、Embedding 或 RAG；
- AI Gateway、AI 对话、提示词、代码审查或测试生成；
- 刷新令牌、记住登录、找回密码或用户资料编辑；
- 管理后台、全局通知中心或复杂设计系统；
- 新增端到端测试框架、状态管理框架、日期库或其他生产依赖；
- 服务端执行任何用户仓库代码；
- 部署、生产反向代理或 CI 工作流。

## 8. 技术约束

1. 使用现有 Vue 3、TypeScript、Vite、Element Plus、Vue Router、Pinia 和 Axios。
2. 使用 Composition API，不迁移技术栈，不混入 JavaScript 页面。
3. 不新增生产依赖；如认为确有必要，先取得项目所有者确认。
4. API 调用集中在 `src/api/`，页面不得自行创建 Axios 实例。
5. 复用 DEV-010 的认证 Store、HTTP 拦截器和错误处理。
6. 页面组件只处理展示和交互；重复或复杂逻辑提取为职责清晰的组件或 composable。
7. 所有异步页面覆盖加载、空数据、失败、重试和成功状态中适用的部分。
8. 前端路由和按钮可见性不作为安全边界。
9. 不持久化项目数据，不记录 Token、项目描述或完整错误响应。
10. 不使用 `v-html` 展示后端或用户输入内容。
11. 不修改 DEV-009 的后端资源归属和 404 隐藏语义。
12. 不修改已执行的 Flyway migration。
13. 不执行来源不可信的用户仓库代码。
14. 新增行为必须具有匹配测试。
15. 只使用 npm 和现有 `package-lock.json`，不引入其他包管理器文件。
16. 无法运行完整检查时必须说明原因和风险，不能虚构通过结果。

## 16. 风险与审查重点

### 16.1 资源存在性泄露

后端会将不存在、已删除和他人项目统一为 404。前端不得根据旧缓存、不同文案或操作入口把这些情况区分给用户。

### 16.2 认证逻辑回归

根路由和登录默认落点变化容易破坏 DEV-010 的会话恢复与安全重定向。审查时应重点覆盖直接打开项目 URL、刷新、令牌失效和登录后返回原路径。

### 16.3 分页状态失真

URL、组件状态和后端响应中的 `page`、`pageSize` 必须一致。删除最后一项、浏览器回退和非法查询参数是重点边界。

### 16.4 重复提交与陈旧响应

快速点击或路由切换可能导致重复写请求，或让较晚返回的旧请求覆盖当前页面。创建、更新、删除和列表翻页都要验证状态隔离。

### 16.5 不可信内容渲染

项目名称和描述来自用户输入，必须按文本展示。任何 `v-html`、直接拼接 HTML 或把内容写入日志的实现都应阻止合并。

### 16.6 JavaScript 数字 ID

当前后端以 JSON number 返回 `BIGINT` ID，前端现有类型体系也使用 `number`。本任务只接受正安全整数并记录这一契约限制，不在前端单方面改成字符串，也不借机修改后端 ID 策略。

### 16.7 构建体积

DEV-010 基线构建已存在大于 500 kB 的 chunk 告警。DEV-011 应优先懒加载新增业务页面并记录构建结果，但本任务不进行 Element Plus 按需导入或全局打包重构；如体积显著恶化，应在 PR 风险中说明并另立任务。

## 17. 回滚方式

本任务不包含数据库或后端契约变更。出现严重问题时可以回滚前端 DEV-011 提交并重新部署上一版静态资源；后端 DEV-009 项目数据不受影响。

回滚或降级过程中不得删除用户项目数据，也不得修改 V4 migration。若发现后端契约缺陷，应单独建立后端修复任务，而不是在本任务中隐式扩张范围。
