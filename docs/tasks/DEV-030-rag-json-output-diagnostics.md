# DEV-030：细分 RAG JSON 输出失败诊断

日期：2026-10-10。基线：`develop` 的 PR #47 合并提交 `420484c`。前置证据见 [DEV-029 评估](../testing/rag-failure-stage-and-quality-assessment.md)：新 Q9 请求的持久阶段为 `RAG_OUTPUT`、类别为 `JSON_SCHEMA`，但原始模型输出未保存，因此无法追认具体 JSON 错误；DEV-027 的更早 Q9 失败同样不能追认。

## 目标与边界

仅细分**未来请求**的 RAG JSON 结构失败，保持公开 `AI_RESPONSE_INVALID` 502、当前严格输出合同、用量、幂等和失败事务语义。此任务不修改提示词、输出 Schema、检索排序、引用规则或提供商请求参数；不对 DeepSeek 发起付费复测，不改写 V11 或历史 `JSON_SCHEMA` 记录。

诊断只写固定枚举。不得保存或记录模型正文、原始 JSON、字段值、字段名、解析器异常 message、提示词、来源正文或上游错误体；公开响应和历史消息不增加诊断字段。新诊断仍受 `rag_invocation_details` 的成对约束，并只在已持久化的 RAG 502 失败上填写。

## 冻结的安全类别

`failure_stage` 继续为 `RAG_OUTPUT`。将当前过宽的 `JSON_SCHEMA` 路径分为以下类别；V12 约束继续允许旧 `JSON_SCHEMA`，但新代码不再写它。

| 类别                 | 判定条件                                                                                           |
| -------------------- | -------------------------------------------------------------------------------------------------- |
| `JSON_ABSENT`        | 网关返回的内容为 `null`。                                                                          |
| `JSON_SIZE`          | 原始字符串超过现有 262144 UTF-16 code units 上限。                                                 |
| `JSON_DUPLICATE_KEY` | 严格重复键检测拒绝；关闭该检测后可解析第一个 JSON 值。此判定仅用于错误分类，绝不发布宽松解析结果。 |
| `JSON_SYNTAX`        | 第一个完整 JSON 值无法解析，且不满足上述重复键判定；包括截断、围栏与非法字符。                     |
| `JSON_TRAILING`      | 第一个 JSON 值完整，但其后还有第二个值或非空非法内容。                                             |
| `JSON_SHAPE`         | 单个合法 JSON 值不是恰好含 `answer` 字符串和 `citationIds` 数组的对象。                            |

判定顺序为缺失、长度、严格解析及重复键复核、尾随内容、顶层形状，再沿用现有 `ANSWER_CONTENT`、`CITATION_IDS`、`CITATION_MARKERS`。若同一输出有多种缺陷，只记录此顺序下首先识别的类别。复核只在严格解析失败时执行，使用同一有界字符串，不调用模型、不保存宽松解析结果，也不读取或记录异常文本。

## 验收标准

1. 先以确定性 fixture 覆盖上述六类、有效输出及原有 answer/引用失败；确认分类互斥、公开错误码不变，异常和持久诊断只含固定值。
2. MySQL 8 / Testcontainers 验证 V12 从空库顺序执行及 V11 升级：旧 `JSON_SCHEMA` 行仍有效，新类别可写，部分/错配/未知类别被拒绝。不得修改已合并的 V11。
3. Stub RAG 集成证明至少一个新 `RAG_OUTPUT` 类别与 `FAILED` 状态原子保存；已接收的 usage 保留；同 UUID 失败重放不再调用模型且不覆盖诊断；成功和非 502 失败仍为 `NULL`。
4. API 文档与验收记录同步更新；`git diff --check`、文档格式及链接检查、相关单元和 MySQL 集成测试通过。CI 不使用真实模型或私人账户。
5. 报告明确区分“新代码可分类的未来请求”和“Q9 现有 `JSON_SCHEMA` 仍未知”。本任务真实请求次数为零，费用为零。
