# DEV-026：真实资料 RAG 回答、检索召回与引用证据评估

日期：2026-10-09。状态：独立复核完成；实际结果、限制与运行时序见[回答逐断言评估](../testing/real-rag-generated-citation-evaluation.md)和[检索复跑评估](../testing/real-rag-retrieval-evaluation.md)。

## 背景与输入

DEV-021/022/023 已提供默认关闭的检索、RAG 对话和引用展示。已有的合成测试能验证协议和来源资格，但不能证明真实生成回答的逐断言事实支撑，也不能从最终引用推断完整检索候选。

本任务使用 `develop` 的 `b0b58142af63963bc36ced05df064e4253475794` 作为资料冻结点，仅上传四份公开 DevMate 文档：根 README、RAG API、需求基线、前端引用验收记录。五个固定问题覆盖当前与规划状态、引用时效与人工核实、来源删除后的合同、历史与当前资料冲突，以及资料中没有生产 JVM 堆值时的弃答。原文件 SHA-256、问题原文和运行 ID 必须进入验收记录。

时序说明：五次真实生成和一次本地检索复跑已在本任务文档建立前完成，分别保留在 Git 忽略目录。无法追溯性地把它们称为“先写任务后执行”。本合同约束**此后的独立复核、结论和 PR 交付**；已发生的两次运行应在报告中按实际时间与边界分别标明。

## 范围与执行顺序

1. 先冻结公开资料、五题、模型/规格、调用次数和安全边界；仅使用项目隔离的临时 MySQL、MinIO、Qdrant 与本地 Embedding。真实 Chat 使用所有者已授权的次数/预算和隐藏输入密钥；后续检索复跑不得再调用付费 Chat。
2. 对真实 RAG POST 保存完整已发布回答、HTTP/调用状态、实际 token 用量、服务端可信引用位置及 SHA。按可核查断言核对候选引用是否直接支持、与冻结资料冲突或资料不足。核心答案正确和引用结构合法须分别判定。
3. 对相同四份资料及五题独立调用检索 API，保存完整 top‑5 顺序、score、来源、ordinal、行号、chunk SHA、`incomplete`、rounds 和 inspectedPoints。score 仅为向量相似度。复跑候选不能冒充原 RAG POST 未保存的候选。
4. 人工列明需要的直接证据位置，并分别核对检索候选、实际引用。无答案题检查弃答，不计入证据位置覆盖分母。对已返回引用用 chunk SHA 比对两次运行的同名次位置，不能由此推断未引用位置完全相同。
5. 完成独立数据校核、文档格式与链接检查，更新文档导航与验收记录，再提交到单一任务分支及面向 `develop` 的 PR；不自动合并。

## 验收标准

- 四份原文件的 SHA-256 与两次运行清单一致；五个问题原文未更换；真实回答记录能与原始响应逐字对应。
- 五题的检索响应及全部 25 个候选均可由来源、行号、score、chunk SHA 复核；逐片重算文本 SHA 和原文件 SHA，报告不一致数。
- 人工证据位置表明确分子、分母、缺失位置和可能的替代证据；同时区分召回前缺失、已提供但未引用、答案生成过度推断。不能把小样本覆盖写成通用 Recall@5 或上线门槛。
- `available=true`、`TOP_K`、成功状态及合法编号不作为事实正确证明。原运行没有保存的候选、提示词实际提供片段、提供商内部版本和生产状态均标为未验证。
- 不提交密钥、原始运行数据、片段正文、容器日志或临时脚本；清理本任务标签下的临时容器。文档格式与相对链接检查通过，PR 记录实际命令和远端 CI 状态。

## 非目标与回滚

本任务不改检索算法、默认开关、API、数据结构或生产配置，不执行未知用户仓库代码，不新增部署或合并 PR。若评估证据不完整，应报告缺口而不是调低验收口径。回滚只需撤销本任务文档提交；不删除共享数据库 migration 或已有用户数据。后续扩大的预注册质量基准需独立任务和验收标准。
