## 2. 目标与交付

形成一套可以进入索引实现的国内 Embedding 规格、费用策略、锁定的隔离向量测试环境和接口合同。
依次交付：

1. 国内官方 API 与本地模型比较及首选结论，注明证据日期和无法核验的项目。
2. 下一编号 ADR：模型、维度、距离、tokenizer、批次/超时限制、费用与未知结果策略。
   技术提议与已接受决策明确区分，不把本次安排当作具体预算确认。
3. 可复现的 tokenizer fixture 和向量 HTTP 合同 fixture，均为合成内容，不含账户凭据。
4. 固定版本与镜像摘要的 Qdrant/MySQL 隔离核验记录，包括实际命令、输出计数和清理方式。
5. 后续索引功能任务书，覆盖 MySQL 工作记录、预算预留、远程调用、完整发布、删除与恢复。

该任务不交付 `INDEXED` 功能，不新增业务 API、migration、SDK 或部署服务。
核验脚本及测试资源只加入完成上述证据所需的范围；依赖和镜像必须说明用途与精确版本。

## 3. 模型核验顺序

优先核验百炼官方文本 Embedding API，备选为自行托管的 Qwen 文本 Embedding 模型。
首版选一种有效规格；不自动切换供应商、模型或维度。

2026-09-28 文档检查发现：百炼官方示例现使用 `qwen3.7-text-embedding` 和按地域/工作空间区分的地址；
不能将旧示例地址、`text-embedding-v4` 或聊天账户配置直接设为默认。
这只是候选入口，账户可用性、返回模型标识、精确 tokenizer、价格和批次限制仍须核验。
依据：[百炼官方向量化说明](https://help.aliyun.com/zh/model-studio/embedding)。

本地备选入口为 [Qwen 官方 Qwen3-Embedding-0.6B 模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)，
其说明提供 tokenizer 示例及最高 1,024 维输出。
不能将该 tokenizer 视为百炼候选模型的 tokenizer，也不能用公开榜单证明 DevMate 的检索质量。
需要分别锁定权重、tokenizer、推理运行时、许可证、修订和文件摘要，并记录实际资源需求。
当前没有部署或下载模型，本地方案也不等于没有硬件成本。

每个候选必须记录：

- 官方 origin、地域、路径、认证方式和重定向规则；服务端白名单不得接受客户端 URL。
- 请求模型 ID、回执模型 ID、维度与距离；远端 alias 的漂移风险和本地规格修订。
- document/query 输入角色、指令前缀、特殊标记、截断与归一化规则。
- 单输入和合计 token 上限、批大小、响应体上限、并发、连接及总操作截止时间。
- 完整响应及 usage 合同、计费单位、地域/币种、价格有效期与未知结果处理。

优先沿用现有 JDK HTTP/JSON 边界；knowledge 只依赖独立 Embedding 能力与内部片段服务，
提供商 DTO 和协议解析留在 ai infrastructure。

## 4. 精确计数与费用边界

1. 用选定模型对应的精确 tokenizer，在发送前计数；包含实际发送的角色前缀和特殊标记。
   不能按字符数乘系数，也不能借用当前聊天输出 token 配置。
2. 锁定实现、词表、许可证、版本与摘要；中英文、Java/Spring、空白、emoji、组合字符和特殊标记
   fixture 必须与官方 tokenizer 一致。CI 不临时联网下载词表。
3. 无法证明 tokenizer 一致性时，该候选不能直接进入按精确 tokens 预留费用的实现；
   给出原因及可验证替代方案，不静默放宽已接受边界。
4. 保留 DEV-017 的活动片段和编号。超限明确失败，不截断、不暗中重分块或丢弃片段。
5. 付费调用默认关闭，未配置有效价格及工作/项目/全局硬额度时可支出额度为 0。
   具体币种、数值和价格有效期在 ADR 中单独明确，旧美元示例不能直接套用。
6. 后续实现使用固定精度金额和 MySQL 原子预留；每次可能付费的尝试都占预算。
   结果未知不自动退款或重复调用；价格过期、usage 缺失/异常及数据库不可写均阻止后续付费请求。

本任务常规验证使用 Stub 和合成 fixture，不发送真实项目文档到提供商。
真实收费冒烟是单独的启用动作，需明确账户、合成输入与金额上限；安排任务不等于开启常驻调用。

## 5. Qdrant 与恢复合同

选择兼容所需 API 的稳定版本，锁定镜像 tag 和 digest；不因最新版本存在就升级已有依赖。
隔离环境仅绑定 loopback，使用独立容器和卷，记录资源上限及任务内清理命令。
依据：[Qdrant 官方 payload 与过滤说明](https://qdrant.tech/documentation/manage-data/payload/)。

需要实际验证：

- collection 按模型规格隔离，固定维度和距离；重复创建及不兼容现有配置明确失败。
- 稳定点 ID 包含处理代、索引代、块序号和规格；重复 upsert 幂等，退役代不覆盖新代。
- payload 只保存归属和来源定位，不复制正文；用户/项目过滤强制由服务端构造。
- 完整来源组合过滤、不同 BIGINT 的无精度损失传输，以及 MySQL 二次校验所需来源字段。
- 写入确认、部分失败、连接/读取超时、响应丢失、进程重启和重复删除。
- 租约过期后旧 upsert 迟到：操作定位须持久保存，不能仅凭一次查询不存在就清除恢复依据。
- 撤销可见性先于清理；原文件与片段父记录不能在未知向量操作尚无持久交接时被提前删除。

核验最小过滤与恢复合同，不在本任务实现公开检索或 RAG。
ADR 0005 的 topK、资格刷新和有界补足留到检索任务实施。
