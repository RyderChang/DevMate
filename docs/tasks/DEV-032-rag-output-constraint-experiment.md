# DEV-032：修正脱敏采集并实验输出约束

日期：2026-10-11。代码基线为最新 `develop` 的 `2cfa244b7478bb0fab463aa94ddfb96899e42542`。
前置 Q9 五次记录在尚未合并的 [PR #49](https://github.com/RyderChang/DevMate/pull/49)；本任务独立从 `develop` 开始，不合并前置 PR。

## 目标与范围

修正采集器将“没有内联 `[Cn]`”误当作“未返回直接证据来源”的判定。每次分别记录引用来源、来源覆盖、内联标记交集、语义结论；没有保存的信息为 `UNKNOWN`。不能靠返回引用数量或正则表达式认定语义正确、证据支持或逐断言就近绑定。DEV-031 原始结果保持不变，第 2、4 次覆盖及三次语义判定不能恢复。

在独立实验工具中比较四组输出约束，使用生产 `ProjectRagPromptBuilder`、`DeepSeekChatGateway` 响应解析和 `RagOutputValidator`。工具位于测试源码与 `scripts/`；应用 JAR、生产配置、请求合同与模板默认值不变。不扩大到 Schema 设计或提供商 Schema 支持。

Q4 排序和全题逐断言引用继续独立：本实验使用 Q4 的原冻结候选，不扩大 topK、不改写查询、不重新排序；只记录核心证据槽的结论与来源集合，逐断言绑定始终为 `UNKNOWN`。不把该实验算作这两项问题的修复。

## 修正的采集合同

| 项目                   | 判定                                                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `returnedCitations`    | 白名单来源定位字段与合法 ID，逐项保留；不含正文。缺失与明确空列表区别记录。                                                     |
| `sourceCoverage`       | 来源 SHA 相同，且引用片段行范围完整包含冻结证据行，才记 `COVERED`；无该来源为 `NOT_COVERED`；未采集为 `UNKNOWN`。               |
| `inlineEvidenceIds`    | 与上述来源 ID 的标记交集；空交集不改变来源覆盖。未采集答案或来源时为 `null`。                                                   |
| `semanticVerdict`      | `SUPPORTED` / `CONTRADICTED` / `INSUFFICIENT` / `UNKNOWN`，由阅读瞬时答案与冻结证据的人工核验填写。不能从 SHA、数量或标记推断。 |
| `claimCitationBinding` | 本任务不做逐断言评审，固定 `UNKNOWN`；有标记交集也不改变。                                                                      |
| Q9 额外事实 / Q10 弃答 | 分别采集固定判定；未评审为 `UNKNOWN`，其他题不作全断言评审。                                                                    |

`collectionVersion=rag-experiment-collection-v2`。成功结果先保存来源映射与未知语义，再打开本机瞬时评审窗口；窗口显示答案及核心证据行，不向终端、文件、日志或 Git 输出正文。关闭窗口中断运行，已采集来源和 usage 保留；不能补发请求。只有人工提交后才记录 `semanticReviewer=OWNER_MANUAL`。

## 冻结实验

输入夹具为 [frozen-inputs.json](../../scripts/rag-output-experiment/frozen-inputs.json)，包含 DEV-027 原十题、七份来源 SHA、按排名的 50 条候选定位及 E1–E17；没有片段或历史答案正文。夹具 SHA-256 为 `5144607270b3fa6b64e988f4921fa9bafbfa7499a97f0d1a89031d5ed0892b26`。本机缓存来自 `tmp/dev-027/results.json`，仅取其显式检索结果，核对原始七文件 SHA、候选全部定位/score 和正文 SHA；不读取其历史模型回答用于本实验。

这是**冻结检索片段的聊天输出实验**，不重新建索引或调用产品 RAG POST；不验证数据库状态、幂等或发布事务。真实响应只在内存中传入生产网关解析与输出校验，失败阶段是离线评估结果，不冒充数据库持久诊断。

每题使用空历史、相同五个完整候选、相同固定项目元数据，经生产构建器生成用户 JSON。四组只改变下表两项；固定 `deepseek-flash`、关闭思考、非流式、1024 输出 tokens，不设 temperature/top_p。每题轮转组顺序（Q1 A/B/C/D，Q2 B/C/D/A，依此循环），串行运行，避免每次都由同一组先预热缓存。项目元数据在本次重建并固定，与 DEV-031 的数据库 ID/时间不保证字节相同，因此历史 3/5 不作为本轮配对基线。

| 组            | 提示词版本                                                                                                                       | `response_format`        |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| A `baseline`  | 原 `project-rag-v1`                                                                                                              | 不设置                   |
| B `example`   | `project-rag-json-example-exp-v1`：保留原规则，增加只有 `answer` 字符串、`citationIds` 字符串数组的完整示例及禁止嵌套/额外键规则 | 不设置                   |
| C `json_mode` | 原 `project-rag-v1`                                                                                                              | `{"type":"json_object"}` |
| D `combined`  | `project-rag-json-example-exp-v1`                                                                                                | `{"type":"json_object"}` |

[DeepSeek JSON Output 文档](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)要求 JSON 提示及目标格式示例，并提示可能为空 content。C 是仅改变参数的诊断对照，未补齐官方推荐的示例条件；D 同时具备示例。JSON 模式不能代替业务形状与引用校验，不保证消除 `JSON_SHAPE`。
