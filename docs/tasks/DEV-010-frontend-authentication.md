## 2. 背景与目标

后端已经提供用户注册、登录、当前用户查询和 JWT 身份认证，但前端工程基座尚未接入这些能力。DEV-010 建立最小、完整且可测试的前端认证闭环：

1. 用户可以注册账号并返回登录页；
2. 用户可以登录并进入受保护页面；
3. 页面刷新后可以通过 `/auth/me` 恢复有效会话；
4. 未登录用户不能进入受保护路由；
5. 已登录用户不会停留在登录或注册页；
6. API 请求自动携带 Bearer Token；
7. 收到 `401` 后清理本地会话并回到登录页；
8. 用户可以主动退出登录；
9. 上述行为由单元测试和组件测试覆盖。

前端路由保护只用于用户体验，不替代后端的身份、权限和资源归属校验。

## 3. 冻结的设计决策

### 3.1 会话存储

访问令牌只保存在 `sessionStorage`，键名为 `devmate.accessToken`。关闭浏览器标签页后令牌不再保留。本任务不使用 `localStorage`、Cookie 或 IndexedDB，也不实现刷新令牌。

令牌不得写入日志、错误消息、URL、前端持久化状态或测试快照。

### 3.2 会话恢复

Pinia Store 首次处理路由前读取令牌并调用 `GET /auth/me`：

- 无令牌时直接视为访客；
- 校验成功时保存当前用户并进入受保护路由；
- 校验失败时清理令牌和用户状态；
- 同一页面生命周期完成初始化后不重复调用 `/auth/me`。

### 3.3 路由语义

- `/login`：仅访客使用；
- `/register`：仅访客使用；
- `/`：要求有效登录态，并展示当前用户和退出入口。

访客进入受保护路由时，登录页通过 `redirect` 查询参数记录原站内目标。登录成功后只接受以单个 `/` 开头的站内路径，拒绝协议 URL 和 `//host` 形式，避免开放重定向。

### 3.4 API 与错误处理

认证 API 统一通过 `src/api/` 的 Axios 实例调用：

- `POST /auth/register`；
- `POST /auth/login`；
- `GET /auth/me`。

请求拦截器在令牌存在时添加 `Authorization: Bearer <token>`。响应拦截器收到 `401` 时清理会话并通知应用跳转登录页。

表单可以展示后端返回的可读 `4xx` 业务消息；网络错误和 `5xx` 只展示前端通用提示，避免暴露服务端内部细节。

### 3.5 开发代理

浏览器默认使用 `/api` 作为 Axios 基础路径。Vite 开发代理转发到后端时移除 `/api` 前缀，使请求与后端实际的 `/auth/*` 路径匹配。生产环境可通过 `VITE_API_BASE_URL` 配置实际 API 基础地址。

## 4. 实现范围

### 4.1 API 与类型

新增认证请求、响应、用户和统一响应类型；封装注册、登录和当前用户 API；集中处理安全的错误文案。

### 4.2 Pinia 认证 Store

认证 Store 负责：

- 登录和令牌写入；
- 注册请求状态；
- 页面刷新后的会话恢复；
- 当前用户状态；
- 主动退出和失效会话清理；
- 表单提交期间的加载状态。

### 4.3 页面与布局

登录和注册页使用 Element Plus 表单，覆盖必填、长度和确认密码校验。注册成功后不自动登录，返回登录页并显示成功提示。

受保护布局展示当前用户昵称（无昵称时展示用户名）和退出按钮。首页只作为认证闭环的最小落点，不提前实现项目列表或其他业务模块。

### 4.4 自动化测试

引入 Vitest、Vue Test Utils 和 jsdom，覆盖：

- Store 登录、注册、会话恢复、无效会话和退出；
- HTTP Bearer 请求头与 `401` 清理；
- 访客、有效会话和访客专用页面的路由守卫；
- 登录表单规范化、站内返回和外部重定向拒绝；
- 注册确认密码校验、成功跳转和不自动建立会话。

## 5. 非目标

DEV-010 不实现：

- 项目列表、详情、创建、编辑或删除页面；
- 管理员页面或前端细粒度权限系统；
- 刷新令牌、记住登录、跨标签页同步或单点登录；
- 找回密码、邮箱验证、修改密码或用户资料编辑；
- OAuth、第三方登录或验证码；
- AI 对话、RAG、GitHub、代码审查或测试生成；
- 后端认证、RBAC 或数据库变更；
- 部署、生产反向代理或 CI 工作流。

## 8. 风险与后续边界

- `sessionStorage` 可以降低跨浏览器会话持久化范围，但不能抵御 XSS；后续页面仍必须避免不可信 HTML 渲染并持续使用后端权威校验。
- 当前后端只返回访问令牌，本任务无法无感刷新过期会话；令牌过期后用户需要重新登录。
- 前端路由元数据不是授权边界；项目所有权仍由后端 DEV-009 的查询条件保证。
- 下一任务建议实现前端项目空间，并复用本任务的认证 Store 和统一 HTTP 客户端。
