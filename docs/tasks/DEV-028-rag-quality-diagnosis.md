## 范围与方法

- **502**：沿 RAG 服务、DeepSeek 网关和输出校验的错误映射逐段追踪；检查返回错误、成功请求 usage、现有单元测试和可保留的本地日志。可用不联网 Stub 证明某种输入会产生同一错误，但不能把“可复现的可能路径”写成三次真实请求的确定根因。若原始提供商响应、结束原因或失败 usage 不可用，明确列出缺失的诊断信息；不读取或记录密钥。
- **Q4 召回**：核对冻结源 SHA、片段行区间、处理分块规则和 Q4 top‑5 的全部候选与 score。必要时可用同规格本地模型与七份公开文档做一次无付费的隔离检索，扩大 Q4 的 `topK` 以观察 E7 的排名；另一次运行只作诊断，不回写 DEV-027 固定 top‑5 结果。区分“已索引但排名靠后”“未建立合格片段”“来源过滤/状态改变”和“无法判断”。
- **过度断言**：把每条有问题的原句拆成原子事实，逐一核查返回引用、冻结源文档、当前 API 合同及相关实现；确认何处是错误、何处只是证据不足或措辞过宽。检查提示词与输出校验的职责边界，提出最小修复候选，不在本任务改变提示词、模型、检索排序或安全校验。

证据分级：**确认**须有原始响应或可复现的确定性代码/数据证据；**可能**有兼容现象的机制但缺少区分性观测；**未知**缺少关键输入。不得凭 HTTP 502 断言模型截断、JSON 格式错误或检索缺口导致失败。
