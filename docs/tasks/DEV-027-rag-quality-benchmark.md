## 实验合同与预算

- 将七份文档上传、解析并显式索引到本任务独占的临时项目。每题先以原文调用一次 `knowledge/search`、固定 `topK=5`，记录全部候选及完整来源定位；随后在**独立空历史对话**提交一次 RAG POST，记录原样回答、结构化引用、状态与实际 usage。最多 10 次真实 Chat 请求，失败不自动重试、不额外问模型。两次调用之间不修改资料。
- 固定本地 Qwen3-Embedding-0.6B 的 `qwen3-0.6b-1024-cosine-v1`，Chat 使用 DevMate 官方 DeepSeek 适配器的 `deepseek-flash`，非流式、关闭思考、`project-rag-v1`、输出上限 1024 tokens。不得切换到其他付费模型。临时运行脚本仅在 Git 忽略目录保存结果与片段正文，密钥由所有者在本机隐藏输入，不写入文件、命令行、日志或 Git。
- 所有者授权**最多 10 次且不超过人民币 5 元**。2026-10-09 核查的 [DeepSeek 官方人民币价目](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) 中，`deepseek-flash` 高峰价按输入缓存未命中 2 元/百万 tokens、输出 8 元/百万 tokens。DevMate 单请求最多 96 KiB 输入封装、1024 输出 tokens；即使用每输入字节对应一个 token 的保守上界，十次上界约 2.05 元。运行前须再次核价；若价格或模型限制变化使上界不能证明低于 5 元，停止真实 Chat。记录实际 usage；账单金额只能由所有者在提供商平台确认，不用估计代替账单。
- 本任务不部署、不更改后端/前端行为、不执行上传文档中的指令，不发送私人仓库内容。容器仅用本任务标签，结束时按准确名称和标签清理，不全局 prune；UNKNOWN journal 不随意删除。

## 预冻结判定与验收

1. **检索覆盖**：仅 Q1–Q9 的 17 个 E 槽为分母。按完整 top‑5 与原文件行/SHA 计算微观覆盖 `命中 E / 17`，另列九题中“全部 E 命中”的题数。报告每个缺失槽、候选排名与 `incomplete`；`TOP_K` 和高 score 不等于足够证据。
2. **回答核心事实**：逐题逐 E 判断“有正确结论且已返回引用区间直接支持 / 正确但引用不足 / 与冻结资料矛盾 / 未回答”。Q10 单独判定是否明确弃答、是否编造生产点数。额外可核查事实逐条标记支持或证据不足，不因核心答案正确而忽略过度推断。
3. **阶段归因**：分别报告完整检索候选、原 RAG 返回引用、模型回答；未暴露的“实际提供给模型但未引用的片段”标为不可观测，除非取得可核验快照。即使检索复跑与引用编号/片段 SHA 一致，也不能伪称两次调用的未引用候选完全相同。
4. **完成条件**：先提交本文档与固定题集，再开始任何上传/索引/检索/Chat。记录所有实际请求、失败、用量、人工判定与限制；校验七份来源 SHA、返回 chunk SHA、文档格式和链接。只将脱敏、公开材料的最小结果写入验收文档；原始响应留在忽略目录。新 PR 目标为 `develop`，最终合并由所有者决定。

回滚为撤销本任务的文档/评估脚本提交；不修改共享 migration、持久用户数据或上一个任务的 PR。若密钥、模型服务、Docker 或预算约束无法满足，先完成无需它们的验证，再明确报告缺失的验收项，不把部分结果当作完整质量结论。
