## 4. 范围与交付

### 4.1 GitHub Actions 质量门禁

新增最小工作流，使用 GitHub 托管的 Ubuntu runner，分别运行后端和前端检查：

- 对目标为 `develop`、`main` 的 `pull_request` 运行，也在 `develop` push 与手动触发时运行；
- 使用稳定且独立的 job 名称，避免路径过滤导致预期检查长期缺席；
- 默认权限仅 `contents: read`，不使用 `pull_request_target` 执行 PR 代码；
- 不使用部署、推送或写仓库权限，不访问私人账户、生产服务或付费模型；
- 第三方 Action 固定到经核实的完整提交 SHA，并注释版本；不得猜测 SHA；
- Java 固定主版本 21，Node 读取现有 `.nvmrc`，npm 固定现有 `packageManager` 版本；
- 缓存 Maven / npm 下载依赖并绑定依赖文件，不缓存 `node_modules` 或数据库数据；
- 每个 job 设置明确的超时（建议后端 20 分钟、前端 15 分钟）；同分支过时运行可取消；
- 不使用 `continue-on-error`、跳过测试、关闭安全校验或隐式重试掩盖失败；
- Maven 测试报告在失败时仍可上传，短期保留（建议 7 天），不上传环境变量、数据库或完整应用日志；
- 无需仓库 secret 即可运行。测试只使用临时隔离数据；新增凭据应在运行时生成且不回显。

后端直接执行 Maven Wrapper 的 `clean verify`，复用已有 Testcontainers 测试；
不得新增平行 MySQL service container、改用 H2、修改 V1 至 V4 或将 Docker 不可用当作通过。
运行前用 `docker info` 检查运行环境。

前端使用 `npm ci` 和现有 lockfile，运行类型检查、Lint、格式、测试、构建与 `npm audit`。
保持现有零已知漏洞验收要求；发现漏洞时记录具体影响并另立修复，不在本任务自动运行 `npm audit fix`。
审计依赖公共 registry，网络故障应明确失败，不能伪报安全通过。

只提交工作流，不自动更改 GitHub 分支保护设置。PR 应列出实际 job 名称供所有者按需设置 required checks。

## 5. 浏览器与接口验收矩阵

使用隔离本地环境和两个临时普通用户 A、B，不连接生产数据，不在报告中保存令牌。

| 场景                                 | 预期证据                                             |
| ------------------------------------ | ---------------------------------------------------- |
| 注册、登录、刷新受保护 URL、退出     | 会话恢复和登录重定向正常，退出后不能访问受保护数据   |
| 空列表创建、查看、编辑               | 表单校验、成功导航与刷新后的服务端数据一致           |
| 分页、切换页大小、前进后退           | URL 与服务端分页一致，非法参数规范化                 |
| 取消删除、确认删除、删除页末最后一项 | 取消不发请求，确认后列表刷新或回前一页，详情跳转合理 |
| B 读取、更新、删除 A 的项目          | 后端统一 404，不泄露是否存在；B 的列表不含 A 的项目  |
| 不存在与已删除项目                   | 与他人项目使用相同不可用语义                         |
| 无令牌、过期令牌                     | 401 与前端会话清理正常，不保留前一用户的项目快照     |
| 网络故障与恢复                       | 明确失败和重试，不伪报写入成功                       |
| 快速切换路由、旧请求延迟返回         | 不发生旧数据覆盖或陈旧删除结果导航                   |
| 320px 与桌面、键盘操作               | 核心 CRUD 可操作，长文本不破坏布局                   |
| 不可信项目名称 / 描述                | 仅文本显示，无 HTML 执行                             |

后端已有自动测试覆盖的权限、事务回滚、RBAC、分页边界和 migration 行为仍必须保持通过。
不为模拟错误在生产代码新增调试接口，也不放宽安全配置。
