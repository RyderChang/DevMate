## 3. 已确认的解析规则：确定性的文本视图

- 仅处理 DEV-016 已接收的 UTF-8 `.txt` / `.md`；重新验证实际长度和原字节 SHA-256。
  原文件不得修改、覆盖或用解析结果替换；完整性不符时处理失败，保留 `STORED` 的原文件记录供排查。
- 使用 JDK 的严格 UTF-8 解码，不引入通用文档解析依赖。去除开头的一个 UTF-8 BOM，
  将 CRLF 与单独 CR 转为 LF。正文不做 NFC、trim、空白折叠或大小写转换。
- Markdown 保留原有标题、链接、代码围栏和 HTML 字面文本，不渲染、不执行、不抓取链接、不读取外部 include。
  这是文本解析与分块，并不承诺 Markdown 语义树或完整代码块。
- 规范化后的文本 SHA-256 按其 UTF-8 字节计算，独立于原字节 SHA-256。
  解析规则标识为 `utf8-text-v1`；规则变化必须产生新版本，不能原地改写既有片段。
- 位置统一指向规范化文本：从 0 开始的 Unicode code point 半开区间 `[start, end)`，
  不使用 UTF-16 索引、原文件字节偏移或 tokenizer 索引。行号从 1 开始，按 LF 计数。
  对外必须注明位置基于规范化文本；首版不提供原字节偏移映射。
- 文本仅作为不可信数据。正文不能更改系统指令或触发工具；日志、错误、审计不保存正文、文件名、对象路径。
  临时内容使用有界缓冲或受控临时文件，成功、失败、取消及崩溃恢复均有清理策略。

## 4. 已确认的分块策略：可复现的字符规则

采用固定策略 `text-window-v1`，不向调用方开放任意参数。
该规则采用字符计数，不宣称满足任一 Embedding 模型的 token 上限。

| 参数               | 确认值                      |
| ------------------ | --------------------------- |
| 普通目标长度       | 1,000 个 Unicode code point |
| 寻找边界的最小长度 | 800 个 Unicode code point   |
| 单块硬上限         | 1,200 个 Unicode code point |
| 相邻块重叠         | 100 个 Unicode code point   |
| 块序号             | 从 0 开始，按文档内位置递增 |

确定性算法：

1. 从 `start = 0` 开始。若剩余文本不超过 1,200 个 code point，取至全文末尾并结束。
2. 否则在 `[start + 800, start + 1000]` 内选择最后一个段落边界。
   首版段落边界严格定义为连续两个 LF 之后的位置；边界行分隔符属于前一块。
3. 没有段落边界时，选择该区间内最后一个 LF 之后的位置；仍不存在则在 `start + 1000` 硬切。
   超长行、代码围栏均服从硬上限，不为保留语义而生成无界块。
4. 保存 `[start, end)` 的完整子串，再从 `end - 100` 开始下一块。
   非末块至少 800 个 code point，必须前进；末块不再创建下一块。

同一原文、解析版本和分块策略必须得到相同的规范化摘要、块数量、文本、区间及顺序。
不能拆开 Unicode surrogate pair；首版不承诺保留组合字素或完整句子。
每个文本位置至少被一块覆盖；重叠和相同文本允许重复，不能只按内容摘要跨块或跨文档去重。
超过数量或字节上限必须整代失败，不能静默截断、跳块或发布部分结果。

## 5. 已确认的资源与持久化边界

| 限制         | 确认值与含义                                                                                    |
| ------------ | ----------------------------------------------------------------------------------------------- |
| 原文件读取   | 沿用 5 MiB；实际字节超限或 SHA 不匹配即失败                                                     |
| 每代片段     | 最多 8,192 块，片段文本 UTF-8 字节合计最多 8 MiB，包含重叠                                      |
| 项目片段额度 | 最多 256 MiB 文本 UTF-8 字节；活动、暂存、待清理代与未消费预留均计入                            |
| 同一文档     | 一次在途处理；活动、暂存、失败残留与退役片段合计最多两代；旧代清理完成前不再启动下一代          |
| 处理时限     | 单次有界读取及解析分块总截止时间 30 秒；2 分钟领取租约                                          |
| 调度         | 每 60 秒扫描，单批最多 20 个到期记录；实例并发最多 2                                            |
| 重试         | 仅对暂时读取/基础设施失败自动重试最多 3 次，分别等待 1/2/4 分钟；确定性校验或限额失败不自动重试 |

片段额度只统计文本与预留，不是 MySQL 实际磁盘占用承诺。
开始前在短事务中预留一代最多 8 MiB；写入暂存文本时将对应预留转为已用字节，不能重复计费或越过额度。
发布或彻底清理后释放剩余预留，失败但尚未清理的文本仍占额度。
上述限制已确认，实施时仍须测试，不作为已经获得的性能结论。

原文件仍只在 MinIO。MySQL 新增处理记录与派生片段，不持久化第二份完整规范化全文。
持久化至少覆盖以下信息，具体 DDL 仍需在实现 PR 中审查：

- 处理记录：自增 BIGINT、用户/项目/文档 ID、generation、原字节 SHA-256、规范化文本 SHA-256、
  解析版本、分块策略版本、状态、块数、文本字节数、额度预留、操作版本/租约、尝试次数和安全错误码。
- 片段：自增 BIGINT、用户/项目/文档 ID、处理记录 ID、块序号、规范化区间、首尾行号、
  文本、文本摘要；首尾行按块包含的第一个和最后一个 code point 的位置确定。
- 幂等请求：归属、请求 UUID、请求指纹、关联处理记录及终态；创建活动代的映射随代保留，
  失败或退役清理后的最小终态保留 24 小时。已完成代的新 UUID 绑定固定保留首次接受后的 24 小时，
  重放不续期；每文档最多 100、每用户/项目最多 10,000 条，过期但未清理及已删除父文档的映射仍占额。
  原子检查与插入，满额对新 UUID 返回受控 409，但不妨碍已有 UUID 重放；完整约束见 ADR 0005。

字段与唯一约束在实施 PR 审查；至少保证处理代唯一、代内序号唯一、归属一致、合法状态与正向区间。
来源标识使用 `UPLOAD`、文档 ID 与原字节 SHA，不把展示文件名作为路径或唯一身份；当前上传源没有 Git commit SHA。
只能新增 Flyway migration，不预定编号、不修改 #30 或其他已共享 migration。
MySQL 保存归属、处理代及发布状态，其他模块通过 knowledge 公开服务调用，不直接查 Mapper。

## 6. 处理、发布和删除

处理状态为 `PENDING`、`PROCESSING`、`CHUNKED`、`FAILED`、`CANCELLED`，独立于存储状态。
只有 `STORED` 且项目有效的文档可以创建任务。上传完成不自动触发处理，避免隐含后台资源消耗。

处理记录与暂存片段先持久化；受限对象读取和 CPU 处理在事务外完成，片段可分批写入暂存区。
最后在短事务中核对项目有效、文档未删除、原 SHA、处理代、操作版本和块清单完整性，原子切换活动代并提交 `CHUNKED`。
读取方只能看到完整活动代。崩溃、重复领取与迟到回调必须通过条件更新隔离；租约只用于领取，不替代发布校验。

暂时失败在剩余次数允许时回到 `PENDING` 并保存下次执行时间，确定性错误或重试耗尽才进入 `FAILED`。
同一处理记录的再次尝试先清理上次暂存，再按新操作版本领取，避免累加重复片段或越过额度。

新代失败时不替换仍有效的旧活动代；新策略、新请求与失败重试均保存自己的记录，不能将旧失败记录改写成成功。
清理失败代后才允许重新启动。同 UUID 的失败重放返回稳定终态；新 UUID 才能发起新的处理尝试。

删除文档或软删除项目时，必须在与发布互斥的短事务中取消处理、撤销活动代可见性并留下持久清理依据。
即使后台线程仍在读取，删除之后也不能发布片段；文本访问始终再次检查用户、项目与文档状态。
片段清理可在数据库内幂等分批完成；原文件清理仍遵循 ADR 0003。
在任何派生内容或其恢复记录尚需父文档定位时，不得先物理删除父元数据并丢失清理依据。
所有原文件、片段及必要恢复工作确认结束后才清账，不用对象存储或未来 Qdrant 的数据库外级联假设。

处理能力使用独立默认关闭开关：关闭时拒绝新任务并暂停领取，既有授权元数据可查询，删除可标记。
已领取任务须在发布时核对开关/取消版本；暂停不能把未完成任务标为成功。
暂停的未完成处理回到待领取状态并使旧尝试失效，删除则进入 `CANCELLED`；两者不能混淆。
数据库片段清理可以继续，原文件远程清理仍受存储开关约束；开启后恢复持久化记录。

## 7. 已确认的 API 边界

不改变 DEV-016 原文件上传、下载限制及存储状态契约；新增端点在独立功能任务中实现。

| 接口                                                               | 确认契约                                                                                                                   |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/projects/{projectId}/documents/{documentId}/processing` | 认证用户显式触发；JSON 含 `clientRequestId` UUID，策略由服务端固定；首次接受返回统一响应和 202                             |
| 同 UUID 重放                                                       | 指纹含文档 ID、原 SHA 和已冻结策略版本；在途返回同一记录及 202，完成返回 200，已失败返回稳定 409；同 UUID 不同指纹返回 409 |
| 相同策略已完成                                                     | 新 UUID 绑定现有活动代并返回 200，不重新分块；已有其他在途任务返回 409                                                     |
| `GET /api/projects/{projectId}/documents/{documentId}/processing`  | 返回处理状态、版本、块数、活动代及安全失败码；区分最近一次处理与仍有效活动代，不返回正文                                   |

用户 ID 来自认证上下文；所有路径均验证用户、项目、文档归属，跨归属与删除返回一致 404。
未 `STORED` 返回 409，开关关闭返回安全 503，额度拒绝返回受控 409，参数错误返回 400。
业务错误码与 DTO 字段在实现 API 文档细化，不暴露提供商异常或对象定位。
重放采用首次冻结的策略；服务端升级默认策略不能改变旧 UUID 的请求含义。
首版不开放正文、片段列表、预览、下载或索引端点；内部片段读取同样受归属、活动代和可见状态约束。

## 8. 独立索引任务必须遵守的边界

以下架构约束已经确认；具体模型、SDK、collection 仍未选择，索引实现尚未授权：

1. knowledge 只依赖 AI Gateway 的独立 Embedding 能力，不能复用聊天提示词来生成向量，
   不能直接引用模型提供商 SDK。输入仅为本代有界片段，输出维度与有限数值必须校验。
2. MySQL 保存索引代、片段清单、Embedding 规格、操作定位、发布状态及失败恢复依据；
   Qdrant 是可重建向量投影，不能替代权限、文档状态或片段真相源。
   不将原文件或第二份片段正文复制进向量 payload，正文由授权的 knowledge 内部服务取得。
3. 每个向量关联用户、项目、文档、处理代、块序号、原 SHA、解析/分块版本和 Embedding 规格。
   点定位由服务端确定，重试不能产生重复点；不同代不能覆盖彼此。
4. 远程 Embedding 与向量操作在事务外执行。索引状态独立，使用
   `PENDING`、`INDEXING`、`INDEXED`、`FAILED`、`DELETE_PENDING`。
   完整清单验证且版本条件更新成功后才发布；部分 upsert 成功不代表 `INDEXED`。
5. 后续检索由服务端强制注入 `userId`、`projectId` 条件；向量命中再经 MySQL 验证活动处理代、
   完整索引代及未删除状态后，才读取正文并送入上下文。不能相信客户端过滤或向量 payload 的单次断言。
6. 删除或换代后先撤销可检索资格，再幂等清理向量。旧回调不能发布；租约过期、一次不存在或请求超时
   不证明远端 upsert 已停止。保存定位和退役代清单，迟到写入须可再次清理；未知结果不得过早清账。
7. 模型或解析/分块策略变化产生新索引代，禁止混合维度、tokenizer 或模型版本。
   新代未完成期间保留仍有效旧代；删除优先于任何代的发布。
   活动处理代一旦切换，旧处理代的向量立即失去检索资格；新代未索引期间返回未索引状态，
   不承诺解析换代期间检索无中断。仅 Embedding 规格换代时，可继续读取同一活动处理代的完整旧索引。
8. 正文与模型输入视为不可信数据；日志和调用记录只保留必要模型、版本、用量、耗时和安全状态，不保存完整输入输出。

索引实施前还需独立确认：提供商/模型与版本标识、向量维度、距离规则、tokenizer 与 token 上限、
超限片段策略、批大小/并发/超时/重试、项目预算与数据外发约束、Qdrant/SDK 精确版本和隔离环境。
当前字符块不是 token 承诺；超限不能静默截断或偷偷改变已发布片段身份。
CI 只用模型 Stub，不调用真实付费模型；真实隔离 Qdrant 合同与 MySQL 兼容性验证留在索引任务。
当前不预建 Embedding 占位接口、collection、向量或 RAG 提示词。
