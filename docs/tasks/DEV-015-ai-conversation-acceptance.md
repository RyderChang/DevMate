3. 使用仓库指定的 JDK 21、Node、npm、Maven Wrapper 和 MySQL Testcontainers 版本，不升级依赖。
4. Docker 可用，创建仅属于本任务的临时数据库、用户和进程；不得连接共享或生产数据。
5. 确认本地 Stub 端口、数据库、后端、前端端口可用；不停止未知进程或复用未知容器。
6. 常规构建与测试保持 AI 默认关闭；启用模型路径只允许指向本任务本地 Stub，不读取真实模型密钥。

### 4.2 可重复的本地模型 Stub

复用适配器测试的响应形状，提供最小可重复的本地 HTTP Stub 及使用说明。可使用现有 JDK、Node
或 Python 标准库，不新增生产依赖、模型 SDK、代理平台或第二套业务服务。

要求：

- 正常路径必须经过浏览器 → 现有 API → 真实后端编排 → 本地 HTTP Stub → MySQL 持久化；
  前端 Mock API 的组件测试不能替代此链路。
- 宿主机运行时只监听 loopback；容器方式仅允许隔离 Docker 网络访问，不向局域网暴露。
- 启用 AI 时，`OPENAI_BASE_URL` 显式指向 Stub 的 `/v1`，使用合成模型 ID；测试认证值运行时生成且不记录。
  不得采用真实凭据，也不得在 Stub 不可用时回退到公共模型地址。
- Stub 支持成功文本、可控延迟、限流、服务错误、无效响应；可通过启动参数选择场景，禁止新增生产故障注入 API。
- 只返回合成内容；请求计数可用于验证幂等，不记录 Authorization、用户消息、完整请求或响应正文。
- 请求体、延迟、并发及运行时间有明确上限；实现时记录取值和启动、停止、清理命令。
- 必须允许并发处理以测试同会话冲突；固定串行 Stub 不能作为并发验证依据。
- Stub 若启动失败或场景不匹配，验证必须失败，不得把默认成功响应当作所有场景通过。

在 `docs/development/local-development.md` 增加隔离对话联调步骤，包括 AI 关闭与 Stub 启用两种模式、
环境变量恢复、容器访问地址差异、故障场景复现和仅清理本任务资源的操作。
使用已有配置，不修改生产默认地址、默认启用状态或安全校验。

## 5. 必须完成的验收矩阵

每项都记录实际证据与结果。复杂时间、并发场景优先使用可控 Stub、同步屏障和测试时钟，避免任意 sleep。

| 场景           | 预期结果与最小证据                                                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| AI 默认关闭    | 真实后端可启动；创建、列表、详情、历史可用；发送返回安全 503，草稿保留；接口与浏览器验证                                                     |
| 创建与发送     | 从项目详情进入、创建默认或自定义标题、发送合成消息；Stub 成功后显示真实持久化的两条消息；刷新后仍可见；浏览器验证                            |
| 对话与消息分页 | 对话 URL 分页、非法参数规范化；至少超过 50 条消息验证最新页、向前加载、顺序和去重；接口与浏览器验证                                          |
| 参数边界       | 空白输入、8000/8001 Unicode code point、emoji、非法 UUID、非法与非安全整数 ID；自动化验证                                                    |
| 所有权隔离     | 两用户、至少两个项目；全部对话 API 对他人、已删除项目、不存在或错配 ID 统一 404，消息无泄露；真实后端接口验证                                |
| 身份与权限     | 无令牌 401、缺少 user authority 403；会话过期后清理页面并登录；API 自动化与浏览器验证                                                        |
| 相同 UUID 重放 | 成功请求以同 UUID、同内容重放，只返回原结果，不新增模型调用或消息；以 Stub 计数及隔离库元数据核对                                            |
| 并发与租约     | 同会话不同请求不能并发生成；409 不启动第二次调用；过期租约可恢复且旧结果不能覆盖新结果；确定性后端测试                                       |
| 失败持久化     | 限流、超时、上游故障、无效响应安全映射，FAILED invocation 与租约释放正确；历史 USER 消息按实际后端契约核对，不伪造助手成功；自动化与接口验证 |
| 不确定网络结果 | 丢弃已到达后端的发送响应，前端保留原 UUID/内容，手动确认复用 UUID；调用数和消息数不增加；确定性测试并记录浏览器复现结果                      |
| 409 与刷新失败 | 禁止新发送，允许手动确认；状态刷新失败有可见提示和重试；不得把失败误报为空历史或已完成；组件与浏览器验证                                     |
| 陈旧响应       | 切换对话、同路由参数变化、组件卸载、退出登录后，旧加载或发送结果不能更新新页面；确定性组件测试                                               |
| 恢复与草稿     | 明确失败保留草稿；历史加载失败保留已有消息；刷新导致 UUID 丢失时先读取服务端状态，不宣称取消调用；浏览器验证                                 |
| 安全文本与显示 | 合成 HTML/脚本标记只按文本显示；超长内容换行；桌面、320px、键盘可完成创建和发送；浏览器与截图                                                |
| 审计与上下文   | provider、model、模板版本、状态、用量和耗时按实际返回记录；上下文有界、远程调用不在事务中；自动化验证                                        |
| 日志与产物     | 不记录密钥、正文、完整 prompt 或上游原始响应；截图和摘要脱敏；检查本次产生的输出，不上传原始日志或数据库                                     |

不确定网络场景必须区分“请求未到服务端”和“服务端已处理但响应丢失”。仅断开浏览器网络不能证明后者，
必须关联 Stub 计数和持久化元数据。可用测试专用代理或拦截实现，但不得改变生产发送接口。
若某浏览器故障注入无法执行，单独记录未执行，不用组件测试冒充浏览器证据。
